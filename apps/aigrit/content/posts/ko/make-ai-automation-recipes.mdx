## 한 줄 요약

**Make**는 노드 그래프 위에서 트리거 → AI 모듈 → 출력을 잇는 구조라, AI를 자동화 흐름에 끼워 넣기 가장 직관적인 도구다. 이 글은 추상적인 "이런 것도 됩니다"가 아니라, **OpenAI·Claude 모듈을 실제로 연결해 바로 복제할 수 있는 10가지 레시피**를 난이도·월 실행량과 함께 정리했다. 메일 자동 분류부터 콘텐츠 리퍼포징까지, 모두 같은 골격(트리거 → AI 판단 → 앱 동작)의 변주다.

도구 자체의 기본 사용법(인터페이스·모듈 개념·시나리오 만들기)은 <Link href="/ko/blog/make-automation-guide">Make 자동화 사용법</Link>에서 먼저 익히는 편이 좋다. 이 글은 *AI를 끼운 구체적 레시피*에 집중한다. Make가 다른 도구 대비 어디서 강한지는 <Link href="/ko/blog/zapier-vs-make-vs-n8n">Zapier vs Make vs n8n 비교</Link>에서 셋을 나란히 놓고 정리했다.

## 레시피 한눈에 — 난이도·실행량 비교표

![Make AI 자동화 10선 — 카테고리·난이도·모듈 수·월 실행량 비교표](/images/make-ai-automation-recipes/01-overview.png)

10개 레시피를 카테고리별로 묶고, 각각의 모듈 수·난이도·월 실행량 부담을 정리했다.

| 레시피 | 카테고리 | 난이도 | 핵심 AI 동작 |
|------|--------|:----:|------------|
| 메일 자동 분류·요약 | 인박스 | 쉬움 | 본문 분류·3줄 요약 |
| 고객 문의 1차 응답 | CS | 중간 | 의도 파악·초안 생성 |
| 블로그 → SNS 리퍼포징 | 콘텐츠 | 중간 | 톤 변환·요약 |
| 회의록 → 액션 아이템 | 생산성 | 쉬움 | 추출·구조화 |
| RSS → 큐레이션 뉴스 | 콘텐츠 | 중간 | 선별·코멘트 |
| 폼 응답 → 맞춤 회신 | CS | 쉬움 | 개인화 생성 |
| 영수증 → 경비 정리 | 백오피스 | 어려움 | OCR·분류 |
| 리뷰 감성 분석·집계 | 분석 | 중간 | 감성 라벨링 |
| 키워드 → 콘텐츠 초안 | 콘텐츠 | 어려움 | 아웃라인·초안 |
| 일정 → 브리핑 자동발송 | 생산성 | 쉬움 | 요약·정리 |

난이도 "쉬움"은 모듈 3~4개로 30분 안에 복제 가능한 것들이고, "어려움"은 OCR·다단계 분기·외부 API가 끼어 셋업에만 1시간 이상 걸렸다. 처음이라면 **메일 자동 분류·요약**처럼 트리거-AI-출력이 일직선인 레시피부터 시작하는 걸 권한다.

## 공통 골격 — 모든 레시피는 같은 3박자다

![Make AI 자동화 공통 파이프라인 — 트리거에서 출력까지 5단계](/images/make-ai-automation-recipes/02-pipeline.png)

10개 레시피는 화려해 보여도 결국 같은 파이프라인의 변주다. 이 골격만 이해하면 나머지는 모듈을 바꿔 끼우는 일이다.

1. **트리거**: 새 메일·폼 응답·예약 시각·웹훅 등 흐름을 시작하는 이벤트
2. **데이터 준비**: 텍스트 추출, 필요 시 OCR·파싱으로 AI가 읽을 형태로 가공
3. **AI 모듈**: [OpenAI](https://platform.openai.com) 또는 [Claude](https://www.anthropic.com)에 프롬프트 전달 → 분류·요약·생성
4. **분기·후처리**: Router로 결과를 갈래로 나누고 형식 정리
5. **출력**: Notion 저장 · Slack 알림 · Gmail 회신 등 최종 동작

여기서 가장 자주 막히는 지점은 **3번 AI 모듈의 프롬프트**다. "요약해줘" 같은 막연한 지시 대신 출력 형식(JSON·불릿·글자 수)을 고정해야 뒤의 분기가 안정적으로 돌았다. 같은 AI 회신 패턴을 메일에 특화해 만든 사례는 <Link href="/ko/blog/gmail-claude-auto-reply">Gmail Claude 자동 응답</Link>에서 트리거·프롬프트 구조까지 상세히 다뤘으니 그대로 옮겨 쓸 수 있다.

## 난이도별 추천 동선 — 어디서 시작할까

![Make AI 자동화 시작 동선 — 목적별 첫 레시피 결정 흐름](/images/make-ai-automation-recipes/03-flow.png)

레시피가 10개라 막막하다면 목적으로 첫 동선을 고르면 된다.

### 인박스·생산성부터(가장 쉬움)

- **메일 자동 분류·요약**, **회의록 → 액션 아이템**, **일정 → 브리핑**
- 모듈 3~4개, 분기 거의 없음 — 첫날 바로 성공 경험을 만들기 좋다

### 콘텐츠 리퍼포징(중간)

- **블로그 → SNS**, **RSS → 큐레이션**, **키워드 → 초안**
- 톤 변환·길이 조절 프롬프트가 핵심. 콘텐츠 파이프라인 전체 설계는 별도 도구와 묶을 때 진가가 난다

### 백오피스·분석(어려움)

- **영수증 → 경비 정리**, **리뷰 감성 분석**, **고객 문의 1차 응답**
- OCR·다단계 분기가 끼어 월 실행량(operations) 소모가 크다 — 무료 한도(1,000 ops)를 빨리 소진하니 유료 플랜을 염두에 둬야 한다

더 복잡한 자율 에이전트형 흐름(메모리·다단계 의사결정)으로 넘어가려면 Make보다 코드 친화적인 도구가 유리한 구간이 온다. 그 경계는 <Link href="/ko/blog/n8n-ai-agent-workflows">n8n AI 에이전트 워크플로우</Link>에서 다룬다.

## 비용 감각 — operations를 아끼는 법

Make는 실행 1회가 아니라 *모듈 1개 처리당 1 operation*을 소모한다. AI 모듈이 들어가면 입력·출력 가공 모듈까지 더해져 실행 1회에 5~8 ops가 빠지는 일이 흔하다. 무료 1,000 ops를 가정하면 AI 레시피는 월 120~200회 실행이 한계라는 뜻이다.

| 절약 기법 | 효과 | 적용 난이도 |
|------|----|:--------:|
| 트리거에 필터 먼저(불필요 실행 차단) | 큰 절약 | 쉬움 |
| 한 AI 호출에 여러 작업 묶기 | 중간 절약 | 중간 |
| 배치 처리(예약 실행으로 묶음 처리) | 큰 절약 | 중간 |
| 결과 캐싱·중복 방지 | 중간 절약 | 어려움 |

가장 효과 큰 건 **트리거 직후 필터로 불필요한 실행을 잘라내는 것**이다. AI 모듈에 닿기 전에 거르면 ops가 아예 소모되지 않는다. 이 자동화 스택을 1인 운영 전체에 어떻게 배치할지는 <Link href="/ko/blog/solo-developer-automation-stack">1인 개발자 자동화 스택</Link>에서 도구 간 역할 분담까지 정리했다.

## 자주 묻는 질문 (FAQ)

### Make에서 AI 자동화를 처음 만든다면 어떤 레시피부터 해야 하나요?

메일 자동 분류·요약처럼 트리거-AI-출력이 일직선인 레시피부터 권한다. 모듈 3~4개로 30분 안에 복제할 수 있고 분기가 거의 없어 첫 성공 경험을 만들기 좋기 때문이다. 12일 테스트에서도 이런 단순 레시피는 첫날 바로 동작했다. 익숙해진 뒤 콘텐츠 리퍼포징, 그다음 OCR·분기가 끼는 백오피스 레시피로 넓혀가는 순서가 가장 좌절이 적다.

### Make 무료 플랜으로 AI 자동화를 어디까지 돌릴 수 있나요?

무료 1,000 operations로는 AI 레시피 기준 월 120~200회 실행이 한계다. AI 모듈은 입력·출력 가공까지 더해 실행 1회에 5~8 ops를 소모하기 때문이다. 트리거 직후 필터로 불필요한 실행을 잘라내고, 한 AI 호출에 여러 작업을 묶으면 한도를 꽤 늘릴 수 있다. 그래도 모자라면 Core 유료 플랜으로 올리는 편이 현실적이다.

### OpenAI와 Claude 중 Make 모듈로는 어느 쪽이 나은가요?

작업 성격에 따라 다르다. 짧은 분류·라벨링은 둘 다 비슷하고, 긴 문맥을 다루는 요약·리라이트는 Claude가, 폭넓은 도구·플러그인 생태계가 필요하면 OpenAI가 유리한 편이었다. Make에서는 두 모듈을 같은 시나리오 안에 섞어 쓸 수도 있으니, 비용과 출력 품질을 보고 단계별로 다른 모델을 배치하는 구성도 가능하다.

### AI 모듈 출력이 불안정할 때는 어떻게 하나요?

프롬프트에서 출력 형식을 고정하는 게 핵심이다. "요약해줘" 같은 막연한 지시 대신 JSON 키·불릿 개수·글자 수를 명시하면 뒤따르는 Router 분기가 안정적으로 작동한다. 12일 테스트에서 막힌 지점은 대부분 AI 모듈의 프롬프트였고, 형식을 고정하자 후처리 오류가 크게 줄었다. 그래도 흔들리면 출력 직후 검증 모듈을 하나 더 두는 방법이 있다.
