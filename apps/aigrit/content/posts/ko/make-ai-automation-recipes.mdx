## 한 줄 요약

**Make**는 노드 그래프 위에서 트리거 → AI 모듈 → 출력을 잇는 구조라, AI를 자동화 흐름에 끼워 넣기 가장 직관적인 도구다. 이 글은 추상적인 "이런 것도 됩니다"가 아니라, **OpenAI·Claude 모듈을 연결해 복제할 수 있는 10가지 레시피**를 난이도와 함께 정리했다. 메일 자동 분류부터 콘텐츠 리퍼포징까지, 모두 같은 골격(트리거 → AI 판단 → 앱 동작)의 변주다.

<Callout type="info" title="이 글의 기준">
  레시피 구성은 Make의 공개 기능(2026년 10월 확인)을 바탕으로 설계한 예시다. 셋업 시간이나 실행당 소모량은 시나리오 구성과 데이터 크기에 따라 달라지므로 수치로 단정하지 않는다. Make는 과금 단위를 크레딧으로 안내하니, 실제 소모량은 시나리오 실행 기록에서 확인하자.
</Callout>

도구 자체의 기본 사용법(인터페이스·모듈 개념·시나리오 만들기)은 <Link href="/ko/blog/make-automation-guide">Make 자동화 사용법</Link>에서 먼저 익히는 편이 좋다. 이 글은 *AI를 끼운 구체적 레시피*에 집중한다. Make가 다른 도구 대비 어디서 강한지는 <Link href="/ko/blog/zapier-vs-make-vs-n8n">Zapier vs Make vs n8n 비교</Link>에서 셋을 나란히 놓고 정리했다.

## 레시피 한눈에 — 난이도 비교표

![Make AI 자동화 10선 — 카테고리·난이도·핵심 AI 동작 비교표](/images/make-ai-automation-recipes/01-overview.png)

10개 레시피를 카테고리별로 묶고 난이도와 핵심 AI 동작을 정리했다.

| 레시피 | 카테고리 | 난이도 | 핵심 AI 동작 |
|------|--------|:----:|------------|
| 메일 자동 분류·요약 | 인박스 | 쉬움 | 본문 분류·3줄 요약 |
| 고객 문의 1차 응답 | CS | 중간 | 의도 파악·초안 생성 |
| 블로그 → SNS 리퍼포징 | 콘텐츠 | 중간 | 톤 변환·요약 |
| 회의록 → 액션 아이템 | 생산성 | 쉬움 | 추출·구조화 |
| RSS → 큐레이션 뉴스 | 콘텐츠 | 중간 | 선별·코멘트 |
| 폼 응답 → 맞춤 회신 | CS | 쉬움 | 개인화 생성 |
| 영수증 → 경비 정리 | 백오피스 | 어려움 | OCR·분류 |
| 리뷰 감성 분석·집계 | 분석 | 중간 | 감성 라벨링 |
| 키워드 → 콘텐츠 초안 | 콘텐츠 | 어려움 | 아웃라인·초안 |
| 일정 → 브리핑 자동발송 | 생산성 | 쉬움 | 요약·정리 |

난이도 "쉬움"은 트리거·AI·출력이 일직선인 몇 개 모듈 구성이고, "어려움"은 OCR·다단계 분기·외부 API가 끼어 설정할 것이 많은 구성이다. 처음이라면 **메일 자동 분류·요약**처럼 트리거-AI-출력이 일직선인 레시피부터 시작하는 걸 권한다.

## 공통 골격 — 모든 레시피는 같은 3박자다

![Make AI 자동화 공통 파이프라인 — 트리거에서 출력까지 5단계](/images/make-ai-automation-recipes/02-pipeline.png)

10개 레시피는 화려해 보여도 결국 같은 파이프라인의 변주다. 이 골격만 이해하면 나머지는 모듈을 바꿔 끼우는 일이다.

1. **트리거**: 새 메일·폼 응답·예약 시각·웹훅 등 흐름을 시작하는 이벤트
2. **데이터 준비**: 텍스트 추출, 필요 시 OCR·파싱으로 AI가 읽을 형태로 가공
3. **AI 모듈**: [OpenAI](https://platform.openai.com) 또는 [Claude](https://www.anthropic.com)에 프롬프트 전달 → 분류·요약·생성
4. **분기·후처리**: Router로 결과를 갈래로 나누고 형식 정리
5. **출력**: Notion 저장 · Slack 알림 · Gmail 회신 등 최종 동작

여기서 가장 자주 막히는 지점은 **3번 AI 모듈의 프롬프트**다. "요약해줘" 같은 막연한 지시 대신 출력 형식(JSON·불릿·글자 수)을 고정해야 뒤의 분기가 안정적으로 돈다. AI 출력을 그대로 고객에게 보내는 레시피(문의 응답·맞춤 회신)는 처음에는 *초안 저장*까지만 자동화하고 발송은 사람이 확인하는 구성을 권한다.

## 난이도별 추천 동선 — 어디서 시작할까

![Make AI 자동화 시작 동선 — 목적별 첫 레시피 결정 흐름](/images/make-ai-automation-recipes/03-flow.png)

레시피가 10개라 막막하다면 목적으로 첫 동선을 고르면 된다.

### 인박스·생산성부터(가장 쉬움)

- **메일 자동 분류·요약**, **회의록 → 액션 아이템**, **일정 → 브리핑**
- 모듈이 적고 분기가 거의 없어 첫 성공 경험을 만들기 좋다

### 콘텐츠 리퍼포징(중간)

- **블로그 → SNS**, **RSS → 큐레이션**, **키워드 → 초안**
- 톤 변환·길이 조절 프롬프트가 핵심. 한 달치 SNS 게시물을 묶어 만드는 흐름은 <Link href="/ko/blog/ai-social-content-calendar">AI SNS 콘텐츠 캘린더 자동화</Link>와 함께 보자

### 백오피스·분석(어려움)

- **영수증 → 경비 정리**, **리뷰 감성 분석**, **고객 문의 1차 응답**
- OCR·다단계 분기가 끼어 크레딧 소모가 커지기 쉽다 — 무료 플랜(월 1,000 크레딧)으로 시험한 뒤 유료 플랜을 검토하자. 영수증·고객 정보처럼 개인정보가 들어가는 데이터는 저장 위치와 보관 기간도 정해 두자

더 복잡한 자율 에이전트형 흐름(메모리·다단계 의사결정)으로 넘어가려면 Make보다 코드 친화적인 도구가 유리한 구간이 온다. 그 경계는 <Link href="/ko/blog/n8n-ai-agent-workflows">n8n AI 에이전트 워크플로우</Link>에서 다룬다.

## 비용 감각 — 크레딧을 아끼는 법

Make는 시나리오 *실행 횟수*가 아니라 *모듈이 처리한 작업*을 기준으로 크레딧을 소모한다. 모듈이 많을수록, 반복(Iterator)으로 처리하는 항목이 많을수록 한 번 실행에 드는 크레딧이 늘어난다. AI 모듈의 크레딧 계산 방식은 모듈 종류에 따라 다를 수 있으니 [Make 요금 안내](https://www.make.com/en/pricing)와 실행 기록을 함께 확인하자. AI 제공자(OpenAI·Anthropic)의 API 요금은 Make 크레딧과 별도로 나간다.

| 절약 기법 | 효과 | 적용 난이도 |
|------|----|:--------:|
| 트리거에 필터 먼저(불필요 실행 차단) | 큰 절약 | 쉬움 |
| 한 AI 호출에 여러 작업 묶기 | 중간 절약 | 중간 |
| 배치 처리(예약 실행으로 묶음 처리) | 큰 절약 | 중간 |
| 결과 캐싱·중복 방지 | 중간 절약 | 어려움 |

가장 효과 큰 건 **트리거 직후 필터로 불필요한 처리를 잘라내는 것**이다. AI 모듈에 닿기 전에 거르면 뒤쪽 모듈의 크레딧과 AI API 비용이 모두 줄어든다. 이 자동화 스택을 1인 운영 전체에 어떻게 배치할지는 <Link href="/ko/blog/solo-developer-automation-stack">1인 개발자 자동화 스택</Link>에서 도구 간 역할 분담까지 정리했다.

Make AI 자동화의 핵심은 단순하다. **레시피는 열 개여도 골격은 하나** — 트리거 → 데이터 준비 → AI 모듈 → 분기 → 출력이다. 이 3박자만 손에 익히면 나머지는 모듈을 바꿔 끼우는 응용이다. 인박스·생산성 레시피로 성공 경험을 만들고, 콘텐츠·백오피스로 확장하되 크레딧과 AI API 비용을 함께 확인하는 순서를 권한다.

## 자주 묻는 질문 (FAQ)

### Make에서 AI 자동화를 처음 만든다면 어떤 레시피부터 해야 하나요?

메일 자동 분류·요약처럼 트리거-AI-출력이 일직선인 레시피부터 권합니다. 모듈이 적고 분기가 거의 없어 첫 성공 경험을 만들기 좋습니다. 익숙해진 뒤 콘텐츠 리퍼포징, 그다음 OCR·분기가 끼는 백오피스 레시피로 넓혀 가는 순서가 막히는 지점이 적습니다.

### Make 무료 플랜으로 AI 자동화를 어디까지 돌릴 수 있나요?

무료 플랜은 월 1,000 크레딧이고, 크레딧은 모듈이 처리한 작업을 기준으로 소모됩니다. 몇 번 실행할 수 있는지는 시나리오의 모듈 수와 반복 처리 항목 수에 따라 달라지니 실행 기록에서 소모량을 확인하세요. 트리거 직후 필터로 불필요한 처리를 잘라내면 한도를 아낄 수 있고, AI API 요금은 별도로 나갑니다.

### OpenAI와 Claude 중 Make 모듈로는 어느 쪽이 나은가요?

작업 성격과 비용에 따라 고르세요. 같은 입력으로 두 모듈의 결과를 비교해 보고, 출력 형식을 잘 지키는지와 토큰 비용을 함께 보면 됩니다. Make에서는 두 모듈을 같은 시나리오 안에 섞어 쓸 수 있으니, 단계별로 다른 모델을 배치하는 구성도 가능합니다.

### AI 모듈 출력이 불안정할 때는 어떻게 하나요?

프롬프트에서 출력 형식을 고정하는 것이 핵심입니다. "요약해줘" 같은 막연한 지시 대신 JSON 키·불릿 개수·글자 수를 명시하면 뒤따르는 Router 분기가 안정적으로 작동합니다. 그래도 흔들리면 출력 직후 형식을 검사하는 모듈을 두고, 형식이 맞지 않으면 사람에게 알림을 보내는 경로를 만드세요.
