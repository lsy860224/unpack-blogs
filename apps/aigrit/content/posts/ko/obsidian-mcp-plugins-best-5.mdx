**결론부터: Obsidian을 Claude에 연결하는 길은 크게 세 가지다. ① Local REST API 플러그인의 내장 MCP 서버 ② 커뮤니티 서버 mcp-obsidian ③ vault 폴더를 Filesystem 서버로 여는 방법. 여기에 ④ Dataview ⑤ Templater를 함께 쓰면 Claude가 만든 노트를 정리·집계하기 쉬워진다.**

[Model Context Protocol(MCP)](https://modelcontextprotocol.io)은 AI 앱이 외부 도구·데이터와 표준 방식으로 연결되게 해 주는 오픈 프로토콜이다. MCP 자체 입문과 Claude Desktop 설정 방법은 <Link href="/ko/blog/claude-mcp-guide">Claude MCP 활용법</Link>에 정리했고, 이 글은 그다음 단계 — Obsidian vault에 무엇을 붙일지 — 를 다룬다.

## MCP가 일반 Obsidian 플러그인과 다른 점

기존 Obsidian 플러그인은 vault 안에서 동작한다. 검색·태그·쿼리·템플릿은 훌륭하지만, Claude가 내 노트를 읽고 답을 쓰는 단계까지는 가지 않는다. <Link href="/ko/blog/obsidian-getting-started">Obsidian 시작 가이드</Link>에서 다룬 기본 플러그인만으로도 1인 지식 시스템은 충분히 돌아가지만, AI 연결은 따로 필요하다.

| 항목 | 일반 Obsidian 플러그인 | MCP 연결 |
|---|---|---|
| 동작 위치 | vault 내부 | AI 앱 ↔ vault |
| 실행 방법 | 단축키·명령 팔레트 | 자연어 요청 (작업마다 승인) |
| 결과 | 노트 안에 표시 | 노트 검색·생성·수정 |
| 준비물 | 플러그인 설치 | 플러그인 또는 서버 + AI 앱 설정 |

## 1. Local REST API 플러그인 — 내장 MCP 서버

[Local REST API](https://github.com/coddingtonbear/obsidian-local-rest-api)는 Obsidian vault에 API 키 인증이 걸린 REST API를 열어 주는 커뮤니티 플러그인이다. 기본으로 `https://127.0.0.1:27124`에서 HTTPS(자체 서명 인증서)로 동작하고, 저장소 README에 따르면 `/mcp/` 경로에 **Streamable HTTP 방식의 MCP 서버를 내장**하고 있다.

- **장점** — 별도 서버 설치 없이 플러그인 하나로 시작할 수 있다. Obsidian 앱을 거쳐 동작하므로 vault 구조를 그대로 다룬다
- **주의** — Obsidian이 켜져 있어야 동작한다. API 키는 비밀번호처럼 관리하자

## 2. mcp-obsidian — Local REST API를 쓰는 커뮤니티 서버

[mcp-obsidian](https://github.com/MarkusPfundstein/mcp-obsidian)은 1번 플러그인의 REST API를 호출하는 **Python 기반 커뮤니티 MCP 서버**다. 공식 참조 서버가 아니라 개인이 관리하는 프로젝트라는 점을 알고 쓰자. README 기준으로 다음 도구를 제공한다.

- 파일 목록 조회 (`list_files_in_vault`, `list_files_in_dir`)
- 노트 읽기 (`get_file_contents`)와 검색 (`search`)
- 내용 추가·부분 수정 (`append_content`, `patch_content`)
- 파일 삭제 (`delete_file`)

삭제 도구가 포함돼 있으므로, Claude가 도구 실행 승인을 요청할 때 내용을 꼭 확인하자. Claude Desktop 설정은 `uvx`로 실행한다.

```json
{
  "mcpServers": {
    "mcp-obsidian": {
      "command": "uvx",
      "args": ["mcp-obsidian"],
      "env": {
        "OBSIDIAN_API_KEY": "Local REST API 설정 화면의 API 키",
        "OBSIDIAN_HOST": "127.0.0.1",
        "OBSIDIAN_PORT": "27124"
      }
    }
  }
}
```

`uvx`는 Python 패키지 도구 [uv](https://docs.astral.sh/uv/)에 포함된 명령이라 uv를 먼저 설치해야 한다.

## 3. Filesystem 서버 — vault 폴더를 그대로 열기

Obsidian vault는 결국 마크다운 파일이 담긴 폴더다. MCP 공식 참조 서버인 Filesystem 서버에 vault 경로를 허용 폴더로 지정하면, Obsidian 플러그인 없이도 Claude가 노트를 읽고 쓸 수 있다. 설정 방법은 앞서 소개한 Claude MCP 활용법의 Filesystem 예시에서 경로만 vault로 바꾸면 된다.

- **장점** — Obsidian이 꺼져 있어도 동작한다. 공식 참조 서버라 설정 예시가 많다
- **주의** — 링크·태그 같은 Obsidian 고유 기능을 이해하는 것이 아니라 파일로만 다룬다. 허용 폴더는 vault 하나로 좁히자

터미널에서 일하는 편이라면 vault 폴더에서 Claude Code를 실행하는 방법도 있다. 이 패턴은 <Link href="/ko/blog/obsidian-claude-code-mcp">Obsidian × Claude Code MCP 연결</Link>에 정리했다.

## 4. Dataview — Claude가 쓴 노트를 집계하기

[Dataview](https://github.com/blacksmithgu/obsidian-dataview)는 노트의 frontmatter와 태그를 데이터베이스처럼 조회하게 해 주는 플러그인이다. MCP 서버는 아니지만, Claude와 함께 쓰면 궁합이 좋다.

- Claude에게 노트를 만들 때 `status`, `date`, `tags` 같은 frontmatter를 정해진 형식으로 채우게 한다
- Dataview 쿼리로 그 노트들을 목록·표로 모아 본다
- 쿼리 작성이 어렵다면 Claude에게 원하는 표를 설명하고 DQL 쿼리를 써 달라고 한다

작성자는 블로그 발행 파이프라인 카드를 Obsidian에 두고 Dataview 대시보드로 관리한다. 그 구조는 <Link href="https://babipanote.com/blog/obsidian-seo-dashboard">Obsidian SEO 관제 시스템</Link>에 정리했다.

## 5. Templater — 노트의 틀을 고정하기

[Templater](https://github.com/SilentVoid13/Templater)는 변수와 스크립트를 쓸 수 있는 템플릿 플러그인이다. Claude가 새 노트를 만들 때 매번 형식이 달라지는 문제를 줄이는 데 쓴다.

- 회의록·회고·글 기획 같은 노트 유형별로 템플릿을 만든다
- Claude에게 "이 템플릿 파일의 구조를 따라 새 노트를 만들어 줘"라고 템플릿 경로를 함께 알려 준다
- 템플릿 안의 실행 코드(`<% %>` 구문)는 Obsidian에서 Templater가 실행할 때만 처리된다. MCP로 파일을 직접 만들면 그대로 문자열로 남으니, AI가 채울 부분은 일반 텍스트 자리표시로 두는 편이 깔끔하다

의미 기반으로 비슷한 노트를 찾고 싶다면 [Smart Connections](https://github.com/brianpetro/obsidian-smart-connections)도 함께 볼 만하다. 기본으로 로컬 임베딩 모델을 써서 API 키 없이 관련 노트를 찾아 준다(MCP 서버는 아니다).

## 자주 묻는 질문 (FAQ)

### Obsidian MCP 플러그인은 유료인가요?

이 글에서 다룬 Local REST API, mcp-obsidian, Filesystem 서버, Dataview, Templater는 모두 무료로 쓸 수 있는 오픈소스 프로젝트입니다. Smart Connections도 핵심 기능은 무료이고 로컬 임베딩을 기본으로 씁니다. 다만 Claude 쪽 사용량은 쓰는 요금제에 따릅니다.

### Claude Desktop 외에 다른 AI 앱에서도 쓸 수 있나요?

MCP는 오픈 표준이라 MCP를 지원하는 앱이면 같은 서버를 연결할 수 있습니다. Claude Code, Cursor 같은 도구도 MCP 서버 설정을 지원합니다. 앱마다 설정 파일 위치와 지원하는 연결 방식(로컬·원격)이 다르니 각 앱 문서를 확인하세요.

### vault에 민감한 노트가 있어도 괜찮나요?

로컬에서 서버가 돌더라도, Claude가 읽은 노트 내용은 대화의 일부로 AI 서비스에 전달됩니다. 민감한 노트는 별도 vault로 분리하고, Filesystem 서버라면 허용 폴더를 좁히세요. 도구 실행 승인 요청에서 어떤 파일을 읽고 쓰는지 확인하는 습관도 중요합니다.

### 한국어 노트 검색이 잘 안 됩니다. 어떻게 해야 하나요?

키워드 검색은 띄어쓰기나 표기가 조금만 달라도 결과가 비기 쉽습니다. 검색어를 여러 형태로 바꿔 요청하거나, 노트에 태그와 frontmatter를 일정하게 붙여 두면 찾기 쉬워집니다. 의미 기반 검색이 필요하다면 Obsidian 안에서 Smart Connections를 함께 쓰는 방법도 있습니다.

### 여러 MCP 서버를 동시에 연결해도 되나요?

기술적으로는 가능하지만 같은 vault에 여러 연결 방식을 동시에 붙이는 것은 권하지 않습니다. 같은 노트를 서로 다른 경로로 수정하면 어떤 변경이 언제 일어났는지 추적하기 어렵습니다. 연결 방식은 하나만 쓰고, Dataview·Templater처럼 vault 안에서 동작하는 플러그인을 보조로 두세요.

## 마무리

Obsidian과 Claude를 잇는 방법은 생각보다 단순하다. 플러그인 하나(Local REST API), 커뮤니티 서버(mcp-obsidian), 또는 공식 Filesystem 서버 중 하나를 고르고, Dataview와 Templater로 정리 체계를 갖추면 된다. 시작 전에 vault를 백업하고, 읽기 요청부터 시험해 보자. 노트앱 자체를 다시 고민 중이라면 <Link href="/ko/blog/notion-alternatives-best-5">Notion 대체 앱 BEST 5</Link>에서 Obsidian이 맞는 선택인지 함께 비교할 수 있다.
