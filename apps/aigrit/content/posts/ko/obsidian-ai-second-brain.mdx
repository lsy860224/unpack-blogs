## 한 줄 요약

노트는 쌓는 게 아니라 *다시 꺼내 쓰는* 게 핵심이다. **[Obsidian](https://obsidian.md)**의 로컬 마크다운 위에 AI를 얹으면, 형식 없이 던져 둔 메모에 태그와 요약이 붙고 관련 노트가 이어져 *다시 찾을 수 있는 상태*가 된다. 이 글은 그 흐름을 **캡처 → 정리 → 연결 → 회수** 4단계로 나누고, 단계마다 AI에 맡길 일과 사람이 남겨야 할 판단을 정리한다.

<Callout type="info" title="이 글의 기준">
  AIGrit 운영 기록(발행 일정·SEO 점검)도 Obsidian 볼트에 쌓고 있지만, 이 글의 시간 절감이나 검색 성공률 같은 수치는 측정하지 않았으므로 적지 않았다. 워크플로우 구조와 예제 스크립트, Obsidian 공식 정보(2026년 10월 확인)를 바탕으로 정리했다.

"제2의 뇌"는 도구 이름이 아니라 *습관의 구조*다. 캡처는 쉬워야 하고, 정리는 미뤄도 무너지지 않아야 하고, 회수는 빨라야 한다. Obsidian을 처음 세우는 기본기는 <Link href="/ko/blog/obsidian-getting-started">Obsidian 시작 가이드</Link>에서 다뤘으니, 이 글은 *AI를 얹어 정리를 덜어 내는* 부분에 집중한다. Obsidian 자체는 개인·업무 용도 모두 무료로 쓸 수 있고, 기기 간 동기화(Sync)와 웹 게시(Publish)만 유료다.

## 워크플로우 전체 그림 — 4단계

![Obsidian AI 제2의 뇌 4단계 — 캡처·정리·연결·회수와 AI의 역할](/images/obsidian-ai-second-brain/01-overview.png)

| 단계 | 하는 일 | AI 역할 | 자동화 수준 |
|------|---------|---------|:-----------:|
| **① 캡처** | 빠르게 메모 쌓기 | 거의 없음 | 사람 |
| **② 정리** | 태그·요약 붙이기 | 허용 목록 안에서 태그 제안, 한 줄 요약 | 자동 + 검수 |
| **③ 연결** | 관련 노트끼리 링크 | 유사 노트 추천 | 반자동 |
| **④ 회수** | 필요할 때 다시 찾기 | 자연어 질문으로 노트 찾기·묶어 답하기 | 자동 |

핵심은 **캡처와 정리를 분리**하는 것이다. 적을 때는 형식을 신경 쓰지 않고 쌓고, 정리는 나중에 AI의 도움을 받아 몰아서 한다. 이렇게 나누면 "정리가 부담돼서 메모를 안 하게 되는" 악순환이 끊긴다. 문서를 *작성하는 자리*에서 바로 정리하는 Notion식 접근과의 차이는 <Link href="/ko/blog/notion-ai-vs-chatgpt-docs">Notion AI vs ChatGPT 비교</Link>에서 볼 수 있다.

## ① 캡처 — 형식 없이 빠르게 쌓기

캡처 단계의 원칙은 *마찰을 최대한 줄이는 것*이다. 모든 캡처는 일단 `00-Inbox` 한 폴더로 모은다.

| 캡처 경로 | 적합한 상황 |
|----------|-------------|
| 인박스 폴더에 바로 작성 | 책상 앞 작업 중 |
| iPhone 단축어 → 인박스 | 이동 중, 떠오른 생각 |
| Obsidian Web Clipper → 인박스 | 기사·문서 수집 |
| 음성 메모 → 텍스트 변환 → 인박스 | 손이 자유롭지 않을 때 |

이 단계에서 AI를 끼우면 캡처가 느려지고, 느려지면 캡처를 안 하게 된다. 태그도 제목도 신경 쓰지 말고 본문만 던져 넣는다.

## ② 정리 — 허용 목록 안에서 태그와 요약을 붙인다

![AI 태깅 규칙 — 허용 태그 목록, 기존 frontmatter 건너뛰기, 제외 폴더, 사람 검수](/images/obsidian-ai-second-brain/02-tag-rules.png)

여기서부터 AI가 일한다. 인박스 노트를 읽어 **태그**와 **한 줄 요약**을 frontmatter에 붙인다. 가장 중요한 규칙은 *태그를 AI 마음대로 만들게 두지 않는 것*이다. 허용 태그 목록을 주고 그 안에서만 고르게 해야 같은 주제가 `ai`, `AI도구`, `인공지능`으로 흩어지지 않는다.

아래는 Claude API로 인박스 노트에 태그·요약을 붙이는 예제 스크립트다. 처음에는 `DRY_RUN = True`로 결과만 확인하고, 볼트를 백업(또는 git 커밋)한 뒤 실제로 적용하자.

```python
# tag_inbox.py — 인박스 노트에 허용 태그·한 줄 요약을 frontmatter로 추가
import json
import pathlib

import anthropic

VAULT = pathlib.Path("~/Obsidian/MyVault").expanduser()
INBOX = VAULT / "00-Inbox"
ALLOWED_TAGS = ["ai", "blog", "seo", "automation", "reading", "idea", "project"]
DRY_RUN = True  # 결과 확인 후 False로 바꿔 실제 적용

client = anthropic.Anthropic()  # ANTHROPIC_API_KEY 환경변수 사용

PROMPT = (
    "다음 노트를 읽고 JSON 객체 하나로만 답해.\n"
    "tags: 허용 목록 {allowed} 안에서만 1~3개\n"
    "summary: 한국어 한 문장 요약\n\n"
    "노트:\n{body}"
)


def ask(body: str) -> dict:
    msg = client.messages.create(
        model="claude-haiku-5-5",
        max_tokens=300,
        messages=[{"role": "user", "content": PROMPT.format(allowed=ALLOWED_TAGS, body=body[:6000])}],
    )
    text = msg.content[0].text
    return json.loads(text[text.find("{"): text.rfind("}") + 1])


for note in sorted(INBOX.glob("*.md")):
    text = note.read_text(encoding="utf-8")
    if text.startswith("---"):  # 이미 frontmatter가 있으면 건너뜀
        continue
    data = ask(text)
    tags = [t for t in data.get("tags", []) if t in ALLOWED_TAGS]
    summary = json.dumps(data.get("summary", ""), ensure_ascii=False)
    front = f"---\ntags: [{', '.join(tags)}]\nsummary: {summary}\n---\n"
    print(note.name, tags, summary)
    if not DRY_RUN:
        note.write_text(front + text, encoding="utf-8")
```

스크립트가 하는 일은 *제안*이고, 결정은 주간 정리 때 사람이 한다. 태그를 훑어보고 어색한 것만 고치면 된다. 같은 일을 스크립트 대신 대화로 하고 싶다면, Claude가 볼트 파일을 직접 읽고 쓰게 연결하는 <Link href="/ko/blog/obsidian-claude-code-mcp">Obsidian × Claude Code MCP 연결</Link>이 손이 덜 간다.

## ③ 연결 — 추천은 AI, 수락은 사람

제2의 뇌가 *그래프*가 되는 건 이 단계다. 임베딩 기반으로 비슷한 노트를 찾아 주는 커뮤니티 플러그인(예: Smart Connections)을 쓰면, 새 노트를 열 때 관련 노트 후보가 옆에 뜬다.

| 연결 방식 | 작동 | 사람의 판단 |
|-----------|------|-------------|
| 유사 노트 추천 | 의미가 비슷한 노트 상위 몇 개 제시 | 링크를 걸지 말지 |
| 주제 허브(MOC) 갱신 | 같은 태그 노트를 허브 노트에 모으기 | 허브 구조 정리 |
| 고아 노트 점검 | 링크가 하나도 없는 노트 목록 | 연결할지, 보관할지 |

완전 자동 연결은 *과잉 링크*로 그래프를 오염시키기 쉽다. 그래서 연결은 **반자동**으로 두고 사람이 마지막에 판단한다. 어떤 플러그인이 AI 연결을 지원하는지는 <Link href="/ko/blog/obsidian-mcp-plugins-best-5">Obsidian MCP 플러그인 추천 BEST 5</Link>에서 비교했다.

## ④ 회수 — 자연어로 묻고 노트로 답 받기

쌓고 정리하고 연결한 이유는 결국 *다시 꺼내 쓰기* 위해서다. AI를 볼트에 연결하면 키워드가 정확히 일치하지 않아도 자연어로 찾을 수 있다.

![Obsidian에 AI를 붙일지 판단하는 기준 — 볼트 규모, 정리 부담, 노트 민감도](/images/obsidian-ai-second-brain/03-flow.png)

- **자연어 검색**: "지난 분기 가격 전략 메모"처럼 물어서 관련 노트를 찾는다
- **볼트 질의응답**: 여러 노트를 근거로 답하게 하고, 출처 노트를 링크로 달게 한다
- **주간 다이제스트**: 이번 주 캡처한 노트를 주제별로 요약해 한 페이지로 만든다

MCP로 Claude를 Obsidian에 연결하는 방법은 <Link href="/ko/blog/claude-mcp-guide">Claude MCP 활용법</Link>에 정리했다. 회수가 쉬워지면 노트를 *쓰는 동기*도 강해진다. 찾을 수 있다는 확신이 캡처를 늘리기 때문이다.

## 주의할 점 — 자동화가 망치는 것들

<ProCon>
  <Pros>
    - 정리 부담이 줄어 캡처를 미루지 않게 됨
    - 허용 태그 목록으로 태그가 일관되게 유지됨
    - 자연어로 묻고 출처 노트로 답을 받는 회수 방식
  </Pros>
  <Cons>
    - 과잉 태깅·과잉 링크: 자동을 방치하면 그래프가 오염됨
    - 클라우드 AI로 노트를 보내면 로컬 우선의 장점이 줄어듦
    - AI 요약이 핵심을 놓칠 수 있어 중요한 노트는 사람이 검수
  </Cons>
</ProCon>

*로컬 우선*이라는 Obsidian의 장점을 지키려면 규칙을 먼저 정하자. 일기·건강·금융 같은 민감한 폴더는 AI 정리 대상에서 빼거나 로컬 모델로만 처리하고, 클라우드 AI에는 공개해도 괜찮은 노트만 보낸다. AI는 정리를 빠르게 할 뿐, *무엇을 남기고 버릴지*는 끝까지 사람의 판단이다.

## 결론 — 캡처는 사람, 정리는 AI, 판단은 다시 사람

**캡처와 회수는 빨라야 하고, 정리와 연결은 AI가 덜어 주고, 마지막 판단은 사람이 한다.** 이 분담이 맞으면 노트는 쌓이는 짐이 아니라 꺼내 쓰는 자산이 된다. Obsidian이 내 용도에 맞는지부터 다시 따져 보고 싶다면 <Link href="/ko/blog/notion-alternatives-best-5">Notion 대체 앱 BEST 5</Link>에서 다른 노트 앱과 비교해 보자.

## 자주 묻는 질문 (FAQ)

### Obsidian에 AI를 붙이면 로컬 저장 장점이 사라지나요?

쓰는 방식에 따라 다릅니다. 노트가 클라우드 AI로 전송되면 그만큼 로컬 우선의 장점은 줄어듭니다. 그래서 민감한 폴더는 AI 정리 대상에서 빼거나 로컬 모델로만 처리하는 규칙을 먼저 정하세요. 공개해도 괜찮은 메모만 클라우드 AI로 정리하면 로컬성과 자동화를 함께 가져갈 수 있습니다.

### 노트가 수백 개인데 지금 시작해도 정리가 될까요?

됩니다. 다만 한 번에 전부 돌리기보다 최근 인박스 노트부터 시작하세요. 예제 스크립트처럼 frontmatter가 없는 노트만 처리하게 하면 이미 정리한 노트는 건드리지 않습니다. 오래된 노트는 검색에 걸릴 때마다 조금씩 정리해도 충분하고, 실행 전에는 볼트를 백업해 두세요.

### AI 태깅이 엉뚱한 태그를 달면 어떻게 하나요?

허용 태그 목록을 주고 그 안에서만 고르게 하세요. 예제 스크립트도 목록에 없는 태그는 버리도록 걸러 냅니다. 목록은 처음에 열 개 안팎으로 작게 시작해 필요할 때 늘리는 편이 관리하기 쉽습니다. 그래도 중요한 노트는 주간 정리 때 사람이 태그를 한 번 훑어보는 단계를 남겨 두세요.

### Notion으로 제2의 뇌를 만드는 것과 무엇이 다른가요?

가장 큰 차이는 파일 소유 방식과 연결 구조입니다. Obsidian은 노트가 내 컴퓨터의 마크다운 파일로 남아 도구를 바꿔도 자산이 보존되고, 백링크로 노트 사이 연결을 쌓기 좋습니다. Notion은 데이터베이스와 협업, 문서 안에서의 AI 작업에 강합니다. 장기 축적과 로컬 소유가 중요하면 Obsidian, 팀 협업과 구조화된 DB가 중요하면 Notion이 맞습니다.
