## 한 줄 요약

**[Cline](https://cline.bot)**과 **[Roo Code](https://roocode.com)**는 에디터 안에서 파일을 읽고 고치고 명령을 실행하는 AI 코딩 에이전트다. Roo Code는 Cline에서 갈라져 나온 포크라 골격은 같지만, Cline은 *모든 동작을 사용자가 승인하는* 흐름을 기본으로 내세우고, Roo Code는 *역할별 모드와 커스텀 모드*로 작업을 나눠 맡기는 데 무게를 둔다. 둘 다 내 API 키로 모델을 고를 수 있어, 비용은 모델 선택과 사용량에서 정해진다.

<Callout type="info" title="비교 기준">
  각 도구의 공식 문서(2026년 10월 확인) 기준으로 실행 환경·승인·모드·모델 연결을 비교했다. 셋업 시간·토큰 비용 같은 수치는 프로젝트와 모델에 따라 크게 달라 제시하지 않고, 대신 내 저장소로 직접 비교하는 방법을 정리했다.
</Callout>

터미널 기반 에이전트와의 차이가 궁금하다면 <Link href="/ko/blog/claude-code-vs-cursor">Claude Code vs Cursor 비교</Link>를 먼저 보면 이 글의 좌표가 잡힌다.

## Cline vs Roo Code — 개요

![Cline·Roo Code 개요 비교 — 실행 환경, 승인, 모드, 모델 연결, 요금](/images/cline-vs-roo-code/01-overview.png)

| 항목 | Cline | Roo Code |
|------|-------|----------|
| **출발** | 독립 프로젝트 | Cline 포크 |
| **실행 환경** | VS Code·JetBrains·CLI 등 | VS Code 확장 |
| **승인 방식** | 모든 동작을 사용자가 승인하는 흐름이 기본 | 모드별 도구 권한, 승인 설정 |
| **모드** | Plan / Act | Code·Ask·Architect·Debug·Orchestrator + 커스텀 |
| **모델 연결** | Cline 사용량 과금, ClinePass, 내 API 키(BYOK) | 내 API 키 등 여러 제공자 |
| **규칙 파일** | `.clinerules` | 커스텀 모드·규칙 파일 |

출처: [Cline 문서](https://docs.cline.bot/introduction/welcome), [Roo Code 모드 문서](https://roocodeinc.github.io/Roo-Code/basic-usage/using-modes/). Cline은 사용량 과금, 월 $9.99의 ClinePass, 내 API 키를 쓰는 BYOK 세 가지 경로를 안내한다(2026년 10월).

## 승인과 모드 — 어디까지 맡기나

두 도구의 차이는 *사람이 어디서 개입하느냐*에서 드러난다.

- **Cline**: 파일 수정·명령 실행 같은 동작마다 승인을 받는 흐름이 기본이다. Plan 모드에서 계획을 세우고 Act 모드에서 실행하는 두 단계로 나뉜다. 무엇이 바뀌는지 보며 진행하기 쉽다
- **Roo Code**: 기본 Code 모드 외에 질문만 답하는 Ask, 설계와 계획을 다루는 Architect(마크다운 파일만 편집), 문제를 추적하는 Debug, 큰 작업을 하위 작업으로 나눠 다른 모드에 맡기는 Orchestrator가 있다. 모드마다 쓸 수 있는 도구가 다르고, 직접 모드를 만들 수도 있다

자동 승인 범위를 넓히면 빨라지는 대신 의도하지 않은 변경과 토큰 사용이 늘 수 있다. 처음에는 승인을 켜 둔 채 쓰고, 반복적이고 안전한 동작부터 자동으로 넘기는 순서를 권한다.

## 모델과 비용 — 도구보다 사용 방식이 정한다

두 도구 모두 Claude·GPT·Gemini·오픈모델 등을 연결해 쓸 수 있다. 비용을 정하는 것은 도구 자체보다 다음 세 가지다.

| 요소 | 비용에 미치는 영향 | 관리 방법 |
|------|------|------|
| **모델 선택** | 성능이 높은 모델일수록 토큰 단가가 높음 | 어려운 단계만 큰 모델 |
| **자동 승인 범위** | 넓을수록 반복 호출이 늘 수 있음 | 안전한 동작부터 단계적으로 |
| **컨텍스트 크기** | 많은 파일을 읽힐수록 입력 토큰 증가 | 작업에 필요한 파일로 범위 좁히기 |

모델·과금 구조를 다른 도구와 비교하려면 <Link href="/ko/blog/github-copilot-vs-claude-code">GitHub Copilot vs Claude Code</Link>를, AI 코딩 도구 전반의 지형은 <Link href="/ko/blog/ai-coding-complete-guide-2026">AI 코딩 완벽 가이드 2026</Link>를 참고하자.

## 내 저장소로 직접 비교하는 방법

![Cline·Roo Code 직접 비교 5단계 — 작업 고르기, 같은 모델, 같은 브랜치, 검토, 사용량 기록](/images/cline-vs-roo-code/02-self-test.png)

1. **실제 작업 2~3개를 고른다** — 한 파일 수정, 여러 파일 기능 추가, 버그 수정
2. **같은 모델·같은 API 키를 쓴다** — 도구 차이만 보기 위해
3. **도구마다 새 브랜치에서 시작한다**
4. **결과를 검토한다** — 테스트 통과, 지시하지 않은 변경, 내가 고친 분량
5. **사용량을 기록한다** — 각 도구가 표시하는 토큰·비용

## 용도별 출발점

![작업 스타일별 출발점 — 단계별 승인과 투명성 vs 역할별 모드와 커스터마이즈](/images/cline-vs-roo-code/03-flow.png)

### Cline이 맞는 사람

- **AI 에이전트가 처음**인 사람: 동작마다 승인하며 무엇이 바뀌는지 본다
- **VS Code 외에 JetBrains나 터미널(CLI)**에서도 같은 에이전트를 쓰고 싶은 사람
- 모델 요금을 따로 관리하기 싫다면 Cline의 자체 과금·ClinePass도 선택지

### Roo Code가 맞는 사람

- **작업을 역할별로 나눠** 맡기고 싶은 사람: Architect로 계획, Code로 구현, Debug로 추적
- **도구 권한을 모드별로 세밀하게** 정하고 싶은 사람
- 팀이나 프로젝트 규칙에 맞춘 **커스텀 모드**를 만들고 싶은 사람

같은 칸을 IDE 통합형이나 터미널에서 채우는 선택지는 <Link href="/ko/blog/cursor-vs-windsurf-vs-claude-code">Cursor vs Windsurf vs Claude Code</Link>에서 비교했다.

## 결론 — 포크는 우열이 아니라 성향

<ProCon>
  <Pros>
    - Cline: 동작별 승인 흐름, VS Code·JetBrains·CLI 지원, 여러 과금 경로
    - Roo Code: 역할별 모드와 Orchestrator, 커스텀 모드와 도구 권한 설정
    - 공통: 내 API 키로 모델을 골라 비용을 직접 통제
  </Pros>
  <Cons>
    - Cline: 승인 단계가 많아 반복 작업에서는 답답할 수 있음
    - Roo Code: 모드가 많아 초기 적응이 필요, 자동 승인을 넓히면 사용량 증가
    - 공통: 모델·키·사용량 관리에 손이 더 감
  </Cons>
</ProCon>

*무엇이 바뀌는지 보며 단계별로*라면 Cline, *역할을 나눠 맡기고 내 규칙으로 다듬으려면* Roo Code에서 시작하자. 같은 모델로 내 저장소에서 비교해 보면 어느 쪽이 손에 맞는지 빨리 드러난다. 에이전트로 앱을 만든 과정은 <Link href="/ko/blog/claude-code-flutter-app-guide">Claude Code + Flutter 앱 만들기 가이드</Link>에서 볼 수 있다.

## 자주 묻는 질문 (FAQ)

### Cline은 어떻게 시작하나요?

VS Code 확장(또는 JetBrains 플러그인, CLI)을 설치하고, Cline 계정의 사용량 과금이나 ClinePass를 쓰거나 내 API 키를 등록한 뒤 채팅 패널에 작업을 지시하면 됩니다. 동작마다 승인을 받는 흐름이라 처음 쓰는 사람도 무엇이 바뀌는지 확인하며 익힐 수 있습니다. Plan 모드로 계획을 세운 뒤 Act 모드로 실행하는 습관을 들이면 좋습니다.

### Cline과 Roo Code는 유료인가요?

두 도구 모두 확장 자체를 설치해 쓸 수 있고, 실제 비용은 연결한 모델의 사용량에서 나옵니다. Cline은 2026년 10월 기준 자체 사용량 과금, 월 9.99달러 ClinePass, 내 API 키를 쓰는 방식을 안내합니다. 내 API 키를 쓰면 모델 제공자에게 사용한 만큼 냅니다.

### Roo Code는 Cline과 무엇이 다른가요?

Roo Code는 Cline에서 갈라져 나온 포크로, Code·Ask·Architect·Debug·Orchestrator 같은 역할별 모드와 커스텀 모드를 앞세웁니다. 모드마다 쓸 수 있는 도구가 다르고 Orchestrator는 큰 작업을 하위 작업으로 나눠 다른 모드에 맡깁니다. 작업을 역할별로 나누고 싶다면 Roo Code, 단계별 승인 흐름이 편하다면 Cline이 맞습니다.

### 어떤 모델을 연결하는 게 좋나요?

작업 난이도에 따라 나누세요. 여러 파일에 걸친 리팩터링처럼 어려운 단계에는 성능이 높은 모델을, 단순 반복 작업에는 저렴한 모델을 쓰는 방식이 비용 대비 효율이 좋습니다. 같은 작업을 두 모델로 시도해 고친 분량과 사용량을 비교하면 내 작업에 맞는 조합을 찾기 쉽습니다.

## 마무리

Cline과 Roo Code는 같은 뿌리에서 나왔지만 사람이 개입하는 방식이 다르다. 단계별 승인이 편한지, 역할별 모드로 나눠 맡기는 쪽이 편한지를 내 저장소에서 확인해 고르자.
