## 한 줄 요약

VS Code 안에서 쓰는 오픈소스 AI 코딩 에이전트 둘을 같은 작업에 붙여 봤다. **[Cline](https://cline.bot)** 은 한 단계씩 승인받으며 또박또박 가는 *안정형*이고, **[Roo Code](https://roocode.com)** 는 Cline에서 갈라져 나온 포크답게 모드 전환·자동 실행·커스터마이즈가 더 공격적인 *속도형*이다. 둘 다 BYO API(내 API 키로 모델 직접 호출) 방식이라, 구독료 대신 *토큰 비용*과 *자율성 수준*을 내가 직접 고른다.

두 도구 모두 "VS Code 확장 → 내 API 키 등록 → 자연어로 작업 지시 → 에이전트가 파일을 읽고 고치고 명령을 실행"하는 골격은 같다. 그런데 *어디까지 내 손을 거치게 하느냐*, *모델을 얼마나 자유롭게 바꾸느냐*에서 성격이 갈렸다. 터미널 기반 에이전트와의 차이가 궁금하다면 <Link href="/ko/blog/claude-code-vs-cursor">Claude Code vs Cursor 비교</Link>를 먼저 보면 이 글의 좌표가 잡힌다.

## Cline vs Roo Code — 개요 비교표

![Cline·Roo Code 개요 비교 — 형태·모델 선택·자동 승인·비용 구조 한눈에](/images/cline-vs-roo-code/01-overview.png)

| 항목 | Cline | Roo Code |
|------|-------|----------|
| **형태** | VS Code 확장 (오픈소스) | VS Code 확장 (Cline 포크) |
| **모델 연결** | BYO API · OpenRouter 등 | BYO API · OpenRouter 등 |
| **자율성 기본** | 단계별 승인 중심 | 자동 승인·모드 전환 적극 |
| **모드 시스템** | Plan / Act 2모드 | Architect·Code·Ask·Debug 등 다중 |
| **커스텀 지시** | `.clinerules` | 커스텀 모드·`.roo` 규칙 |
| **비용 구조** | 토큰 종량(내 API 키) | 토큰 종량(내 API 키) |
| **구독료** | 없음 (도구 무료) | 없음 (도구 무료) |
| **지향점** | 안정·투명한 단계 진행 | 속도·자동화·세분화된 역할 |

핵심 차이는 **자율성의 기본값**이다. Cline은 파일을 고치기 전·명령을 실행하기 전에 보여주고 승인을 받는 흐름이 기본이라 *무엇이 바뀌는지* 투명하다. Roo Code는 같은 뿌리에서 출발했지만 자동 승인 범위를 넓게 열고 역할별 모드를 쪼개 둬서 *한 번 지시하면 멀리 간다*. 둘 다 도구 자체는 무료고, 실제 돈은 API 토큰에서 나간다.

## 셋업과 첫 동작 — 어디까지 만지나

![Cline·Roo Code 첫 동작까지 셋업 시간 비교 — 설치·API 등록·첫 작업 단계별](/images/cline-vs-roo-code/02-scores.png)

같은 작업을 처음부터 붙여 첫 정상 동작까지 걸린 흐름이다. 둘 다 VS Code 마켓플레이스에서 확장을 설치하고, API 키(또는 OpenRouter 키)를 등록하면 바로 채팅 패널이 열린다.

| 단계 | Cline | Roo Code |
|------|:------:|:--------:|
| 확장 설치 | 1분 | 1분 |
| API 키·모델 등록 | 3분 | 3분 |
| 첫 작업 지시·승인 흐름 익히기 | 4분 | 6분 |
| 자동 승인·모드 설정 | 2분(선택) | 5분(모드 다수) |
| **첫 동작까지 합계** | **약 8분** | **약 11분** |

Cline은 Plan/Act 두 모드만 익히면 끝이라 적응이 빨랐다. Roo Code는 Architect·Code·Debug 등 모드가 여러 개라 *처음엔* 무엇을 언제 쓰는지 익히는 데 시간이 조금 더 들었지만, 일단 손에 붙으면 작업을 역할별로 끊어 시키는 맛이 있었다. BYO API라 구독 결제 단계가 없는 점은 양쪽 다 동일하다 — 모델을 어떻게 고를지가 궁금하면 <Link href="/ko/blog/github-copilot-vs-claude-code">GitHub Copilot vs Claude Code</Link>의 모델·과금 구조 정리가 도움이 된다.

## 모델 선택과 비용 — BYO API가 만드는 차이

이 둘의 가장 큰 공통점이자 핵심은 **모델을 내가 고른다**는 점이다. 월 구독으로 묶인 통합 도구와 달리, Cline·Roo Code는 OpenRouter 같은 게이트웨이를 통해 Claude·GPT·Gemini·오픈모델까지 자유롭게 갈아끼운다. 비싼 모델은 똑똑하지만 토큰값이 비싸고, 싼 모델은 반대다 — 그 선택을 도구가 아니라 *내가* 한다.

| 능력 | Cline | Roo Code |
|------|-------|----------|
| 모델 교체 | 작업 중 전환 가능 | 모드별 다른 모델 지정 |
| 컨텍스트 관리 | 자동 요약·파일 선별 | 자동 요약 + 세분 제어 |
| 비용 표시 | 작업별 토큰·비용 누계 | 작업별·모드별 비용 누계 |
| 토큰 절약 옵션 | 승인 단계로 낭비 억제 | diff 적용·캐싱 활용 |
| 오픈모델 활용 | OpenRouter·로컬 가능 | OpenRouter·로컬 가능 |

같은 8일 작업을 동일한 Claude Sonnet 계열 키로 돌렸을 때, **비용을 가르는 건 도구가 아니라 자율성 설정**이었다. Cline은 단계마다 멈춰 승인을 받으니 불필요한 반복 호출이 적었고, Roo Code는 자동 승인을 넓게 열면 빠른 대신 토큰이 더 나갔다 — 자동 승인을 적당히 조이면 비슷한 수준으로 수렴했다. 정리하면 *비용은 모델 선택 × 자율성 폭*의 함수다. 더 넓은 AI 코딩 도구 지형과 모델 과금 기준은 <Link href="/ko/blog/ai-coding-complete-guide-2026">2026 AI 코딩 완벽 가이드</Link>에 종합해 두었다.

## 점수표 — 5개 축 종합

각 축 10점 기준, 8일 실측 인상을 정리한 표다. 절대 평가가 아니라 *둘을 같은 작업에 놓고 비교한 상대 점수*다.

| 축 | Cline | Roo Code |
|------|:------:|:--------:|
| 입문·적응 쉬움 | 8 | 6 |
| 자율성·자동화 | 6 | 9 |
| 변경 투명성·안전 | 9 | 6 |
| 모델·커스터마이즈 자유 | 7 | 9 |
| 비용 통제 | 8 | 7 |
| **합계(50점)** | **38** | **37** |

합계는 거의 동률이다. 점수 분포가 말해 주듯 **Cline은 안전·투명·입문**, **Roo Code는 자율·속도·커스터마이즈**로 강점이 갈린다. "한 줄 차이로 우열"이 아니라 *작업 스타일이 다른 두 도구*라고 읽는 게 맞다.

## 용도별 추천 — 누가 어느 쪽인가

![작업 스타일별 Cline·Roo Code 선택 흐름 — 투명성·자동화·커스터마이즈 분기](/images/cline-vs-roo-code/03-flow.png)

### Cline이 맞는 사람

- **AI 에이전트가 처음**인 사람: 단계별 승인으로 무엇이 바뀌는지 보며 배운다
- **프로덕션 코드에 신중한** 사람: 변경 전 확인이 기본이라 사고가 적다
- **모드는 단순하게**, 흐름은 또박또박 가고 싶은 사람

### Roo Code가 맞는 사람

- **반복 작업을 빠르게 밀어붙이는** 사람: 자동 승인·모드 전환으로 멀리 간다
- **역할별로 끊어 시키고 싶은** 사람: Architect→Code→Debug 모드 분담
- **도구를 내 규칙으로 길들이는** 사람: 커스텀 모드·규칙 파일 자유도

두 도구는 결국 1인 개발자의 코딩 스택에서 *VS Code 안의 에이전트* 칸을 채운다. 같은 칸을 터미널에서 채우는 선택지와 IDE 통합형 선택지를 나란히 보려면 <Link href="/ko/blog/cursor-vs-windsurf-vs-claude-code">Cursor vs Windsurf vs Claude Code</Link>가 좋은 짝이다.

## 자주 묻는 질문 (FAQ)

### Cline 사용법은 어렵지 않나요?

어렵지 않다. VS Code 마켓플레이스에서 Cline 확장을 설치하고, OpenRouter나 Anthropic 같은 API 키를 등록한 뒤 채팅 패널에 작업을 자연어로 지시하면 된다. 8일 테스트에서 첫 동작까지 약 8분이 걸렸고, Plan/Act 두 모드만 익히면 충분했다. 각 단계마다 변경 내용을 보여주고 승인을 받기 때문에 AI 에이전트가 처음인 사람도 안전하게 익힐 수 있다.

### Cline과 Roo Code는 구독료가 따로 있나요?

도구 자체는 둘 다 오픈소스이고 무료다. 비용은 내 API 키로 호출하는 모델의 토큰 사용량에서만 발생한다. 즉 월 정액 구독이 아니라 *쓴 만큼* 내는 종량 구조다. 같은 작업이라도 비싼 모델을 고르거나 자동 승인을 넓게 열면 토큰이 더 나가므로, 모델 선택과 자율성 설정이 사실상의 가격을 결정한다.

### Roo Code는 Cline과 무엇이 다른가요?

Roo Code는 Cline에서 갈라져 나온 포크라 기본 골격은 같지만, 자율성의 기본값이 더 공격적이다. 자동 승인 범위를 넓게 열 수 있고 Architect·Code·Debug 같은 역할별 모드와 커스텀 모드를 지원한다. 한 번 지시하면 멀리 가는 속도와 커스터마이즈 자유가 강점인 반면, 모드가 많아 초기 적응에 시간이 조금 더 들고 자동 승인을 넓히면 토큰 비용이 늘 수 있다.

### 어떤 모델을 연결하는 게 가장 좋나요?

작업 성격에 따라 다르다. 복잡한 리팩터링·멀티파일 수정에는 Claude Sonnet 계열 같은 고성능 모델이 정확도가 높고, 단순 반복이나 비용 절감이 목적이면 더 저렴한 모델이나 오픈모델을 OpenRouter로 붙이면 된다. 두 도구 모두 작업 중 모델 교체가 가능하므로, 어려운 단계는 비싼 모델로, 단순 단계는 싼 모델로 나눠 쓰는 방식이 비용 대비 효율이 좋다.
