## 한 줄 요약

**[Figma](https://www.figma.com)**의 AI는 이제 캔버스 안 보조 기능을 넘어 *외부 AI 에이전트가 디자인을 읽고 쓰는 통로*까지 넓어졌다. 프롬프트로 프로토타입을 만드는 **Figma Make**, 캔버스 안 **Figma 에이전트(베타)**, 그리고 Claude 같은 AI 클라이언트가 디자인을 읽어 코드로 옮기거나 캔버스에 직접 그리는 **Figma MCP 서버**가 축이다. 핵심은 *어디까지 AI에 맡기고 어디서 사람이 확인할지*의 경계를 잡는 것이다.

<Callout type="info" title="이 글의 기준">
  Figma 공식 AI 소개 페이지와 MCP 서버 문서(2026년 10월 확인)를 바탕으로 정리했다. 소요 시간·정확도 수치는 파일 상태와 작업마다 크게 달라 제시하지 않는다. 베타 기능이 많고 요금·한도가 바뀔 수 있으니 쓰기 전 공식 문서를 확인하자.
</Callout>

AI 디자인 도구 전반의 지형과 도입 순서는 <Link href="/ko/blog/ai-design-tools-complete-guide-2026">AI 디자인 도구 완벽 가이드 2026</Link>에 정리했다. 이 글은 *Figma 한 도구 안에서 자동화를 굴리는 방법*에 집중한다.

## 프롬프트로 시작하기 — Figma Make와 에이전트

빈 캔버스에서 시작하는 부담은 **Figma Make**와 **Figma 에이전트**가 줄여 준다. Figma Make는 아이디어나 기존 Figma 디자인을 프롬프트로 프로토타입·웹앱으로 바꾸고, 에이전트는 캔버스 안에서 디자인 생성·변형과 반복 작업을 돕는다.

이 단계의 결과물은 *시작점*으로 보는 것이 안전하다. 톤·여백·타이포 위계, 브랜드에 맞는 디테일은 사람이 다듬어야 한다. 프롬프트로 초안을 뽑는 비슷한 흐름은 발표 자료 쪽에서도 쓰이며, <Link href="/ko/blog/ai-presentation-tools-2026">AI PPT 도구 비교</Link>에서 다뤘다.

## MCP 연동 — 디자인과 코드를 잇기

[Figma MCP 서버](https://help.figma.com/hc/en-us/articles/39252411778583-Figma-MCP-server-FAQs)를 붙이면 Claude 같은 AI 클라이언트가 Figma 디자인을 읽어 코드로 옮기거나, 캔버스에 직접 디자인을 만들 수 있다. 서버는 두 가지다.

- **원격 서버**: `https://mcp.figma.com/mcp`에 연결하고 클라이언트에서 Figma에 로그인한다. 캔버스 쓰기(`use_figma`)와 코드→디자인 변환(`generate_figma_design`)은 원격 서버에서만 된다
- **데스크톱 서버**: Figma 데스크톱 앱의 Dev Mode에서 켠다

![Figma MCP 서버 주요 도구 — 디자인 읽기, 화면 캡처, 캔버스 쓰기, 에셋, Code Connect](/images/figma-ai-design-automation/02-mcp-tools.png)

| 도구 | 하는 일 | 메모 |
|------|---------|------|
| `get_design_context` | 선택한 레이어의 구조를 React·Tailwind 비슷한 형식으로 전달 | 다른 프레임워크는 프롬프트로 요청 |
| `get_screenshot` | 디자인을 PNG로 캡처해 에이전트가 보게 함 | 읽기 도구 사용량 제한 적용 |
| `use_figma` | 플러그인 API로 프레임·컴포넌트·변수·오토 레이아웃 생성·수정 | 베타, 현재 무료 |
| `upload_assets` | 이미지 등 에셋 추가 | |
| Code Connect | 실제 코드 컴포넌트와 Figma 컴포넌트 연결 | 컴포넌트 게시 후 매핑 |

사용량 제한도 확인하자. 2026년 10월 문서 기준으로 View·Collab 좌석은 월 20회까지, Full·Dev 좌석은 Starter에서 쓸 수 없고 Professional은 하루 200회(분당 10회)다. 캔버스 쓰기는 Professional 이상 요금제와 파일 편집 권한이 필요하고, 드래프트 밖 파일에 쓰려면 Full 좌석이 필요하다. 대부분의 MCP 도구는 AI 크레딧을 쓰지 않지만 이미지 생성 같은 일부 도구는 크레딧을 쓴다.

MCP 자체의 구조는 <Link href="/ko/blog/claude-mcp-guide">Claude MCP 활용법</Link>에서 다룬 연결 방식과 같다. 디자인을 코드로 옮긴 뒤의 작업은 <Link href="/ko/blog/ai-coding-complete-guide-2026">AI 코딩 완벽 가이드 2026</Link>의 흐름으로 이어진다.

## 자동화 전에 정리할 것

에이전트가 디자인을 정확히 읽고 쓰려면 파일이 정리돼 있어야 한다. Figma 문서도 에이전트가 *팀의 컴포넌트·변수·레이아웃 규칙*을 기준으로 작업한다고 설명한다.

- **변수**: 색상·간격·타이포를 Figma 변수로 묶어 둔다. 코드로 옮길 때 토큰 이름이 그대로 이어진다
- **컴포넌트**: 반복 요소를 컴포넌트로 만들고 이름을 일관되게 짓는다
- **오토 레이아웃**: 간격·정렬 규칙을 오토 레이아웃으로 정해 둔다
- **Code Connect**: 코드 컴포넌트가 있다면 게시한 뒤 매핑해 에이전트가 실제 컴포넌트를 재사용하게 한다
- **복사본에서 시험**: 캔버스 쓰기는 베타 품질이라 Figma도 복사본이나 드래프트에서 먼저 시험하라고 안내한다

## 실전 워크플로우 — 단계별로 무엇을 맡기나

![Figma AI 디자인 자동화 3단계 — 초안은 AI, 다듬기는 사람, 핸드오프는 MCP와 검수](/images/figma-ai-design-automation/03-flow.png)

### 1단계: 초안은 AI에 맡긴다

- **Figma Make**나 **에이전트**로 화면 초안·프로토타입을 만든다
- 결과는 *완성이 아니라 시작점*으로만 본다

### 2단계: 다듬기는 사람이 한다

- 톤·여백·타이포 위계를 손으로 보정한다
- 색상·간격을 **변수**로, 반복 요소를 **컴포넌트**로 정리한다 (다음 단계 품질에 직결)

### 3단계: 핸드오프는 MCP로 잇고 사람이 검수한다

- **MCP**로 디자인 구조를 코드로 옮기거나, 코드 화면을 Figma로 가져와 검토한다
- 생성된 코드의 반응형 분기·컴포넌트 재사용은 사람이 확인한다
- 이미지 생성 중심의 디자인 도구 비교는 <Link href="/ko/blog/canva-ai-vs-firefly-vs-recraft">Canva AI vs Firefly vs Recraft</Link>에서 따로 다뤘다

## 결론 — 앞단은 AI, 확인은 사람

<ProCon>
  <Pros>
    - Figma Make·에이전트로 빈 캔버스에서 초안까지 빠르게 출발
    - MCP 서버로 외부 AI 에이전트가 디자인을 읽고 캔버스에 직접 작업
    - 변수·컴포넌트를 정리해 두면 디자인과 코드 사이 연결이 쉬워짐
  </Pros>
  <Cons>
    - 에이전트·캔버스 쓰기 등 다수 기능이 베타
    - 좌석·요금제별 MCP 사용량 제한, 일부 기능은 AI 크레딧 소모
    - 정리되지 않은 파일에서는 결과 품질이 떨어지고 검수 부담이 큼
  </Cons>
</ProCon>

Figma 자동화는 *초안은 AI, 다듬기와 검수는 사람, 연결은 MCP*의 3단 구도로 잡으면 안정적이다. 그리고 그 효과는 변수·컴포넌트를 얼마나 정리해 두었는지에 크게 좌우된다. AI 디자인 전체 스택에서 Figma를 어디에 둘지는 앞에서 소개한 AI 디자인 도구 완벽 가이드에서 이어 볼 수 있다.

## 자주 묻는 질문 (FAQ)

### Figma AI로 만든 초안을 실무에 바로 쓸 수 있나요?

초안으로는 유용하지만 완성품으로 보기는 어렵습니다. Figma Make와 에이전트는 빈 캔버스에서 출발하는 부담을 줄여 주지만, 톤·여백·타이포 위계와 브랜드 디테일은 사람이 다듬어야 합니다. 에이전트처럼 베타인 기능은 결과 품질이 들쭉날쭉할 수 있으니 복사본에서 먼저 시험하세요.

### Figma MCP 서버는 어떻게 연결하나요?

원격 서버는 MCP 클라이언트에 `https://mcp.figma.com/mcp`를 등록하고 Figma에 로그인하면 됩니다. 데스크톱 서버는 Figma 데스크톱 앱의 Dev Mode에서 켭니다. 캔버스에 직접 쓰는 `use_figma`는 원격 서버에서만 되고, Professional 이상 요금제와 파일 편집 권한이 필요합니다.

### Figma MCP는 무료인가요?

대부분의 MCP 도구는 AI 크레딧을 쓰지 않지만 좌석별 사용량 제한이 있습니다. View·Collab 좌석은 월 20회, Professional의 Full·Dev 좌석은 하루 200회가 기준입니다(2026년 10월). 캔버스 쓰기는 베타 기간 무료이며 이후 사용량 기반 유료 기능이 될 예정이고, 이미지 생성 같은 일부 도구는 크레딧을 씁니다.

### 디자인 시스템을 정리하지 않아도 효과가 있나요?

초안 생성은 정리 여부와 상관없이 쓸 수 있지만, 디자인을 코드로 옮기거나 에이전트가 캔버스에 작업할 때의 품질은 정리 수준에 크게 좌우됩니다. 색상·간격을 변수로, 반복 요소를 컴포넌트로 정리하고 Code Connect로 실제 코드 컴포넌트와 연결해 두면 에이전트가 팀의 규칙을 따라 작업하기 쉬워집니다.

## 마무리

Figma의 AI는 캔버스 안 보조 기능에서 *외부 에이전트와 디자인을 주고받는 연결점*으로 넓어지고 있다. 초안은 Figma Make·에이전트로 빠르게 뽑고, 다듬기와 검수는 사람이 하고, 코드와의 연결은 MCP로 잇자. 그 전에 변수와 컴포넌트를 정리해 두는 것이 가장 확실한 준비다.
