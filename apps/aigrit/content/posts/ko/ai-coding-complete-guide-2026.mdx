## AI 코딩 도구는 어떻게 나뉘는가

분류 축은 두 가지다. (1) **어디서 개입하는가** — 터미널, 에디터, 데스크톱 앱 (2) **무엇을 다루는가** — 코드 파일, 외부 도구·문서.

| 도구 | 개입 위치 | 다루는 범위 | 대표 활동 |
|---|---|---|---|
| **Claude Code** | 터미널 CLI (IDE 확장·데스크톱 앱도 제공) | 프로젝트 파일 검색·수정, 명령 실행 | 여러 파일에 걸친 기능 구현·일괄 변경 |
| **Cursor** | AI 코드 에디터 (VS Code 포크) | 코드베이스 인덱싱 + `@` 참조 | 자동완성·인라인 수정·에디터 내 에이전트 |
| **Claude Desktop + MCP** | 데스크톱 앱 | MCP로 연결한 파일·DB·서비스 | 노트·문서 조작, 자료 정리 |
| **Obsidian + MCP** | 노트 vault | 마크다운 노트와 메타데이터 | 기획 노트 ↔ 코드 작업 연결 |

처음부터 넷을 다 쓸 필요는 없다. 작업이 코드 위주라면 Claude Code와 Cursor 중 하나로 시작하고, 기획·문서 비중이 크다면 Claude Desktop과 MCP 연결을 먼저 익히는 편이 낫다.

CLI와 에디터의 차이는 <Link href="/ko/blog/claude-code-vs-cursor">Claude Code vs Cursor 비교</Link>에서 자세히 다뤘고, AI 도구 전체 지형에서 코딩 영역의 위치는 <Link href="/ko/blog/ai-tools-2026-guide">2026 AI 도구 완벽 가이드</Link> Pillar에 정리했다. 이 글은 그 위에서 "AI 코딩을 하나의 작업 흐름으로 묶는 법"에 집중한다.

## Claude Code — 결과 단위로 지시하는 도구

[Claude Code](https://code.claude.com/docs/en/overview)는 터미널에서 자연어로 작업을 설명하면 관련 파일을 찾아 읽고, 여러 파일을 수정하고, 테스트 같은 명령을 실행하는 에이전트형 도구다. 수정과 명령 실행은 권한 승인을 거친다. 터미널이 낯설다면 데스크톱 앱이나 VS Code·JetBrains 확장으로도 쓸 수 있다.

핵심은 **`CLAUDE.md`에 적은 프로젝트 규칙을 매 세션 따른다**는 점이다. 코드 스타일, 디렉터리 규칙, 테스트 방법, 커밋 메시지 형식을 적어 두면 매번 같은 컨벤션으로 작업한다. 작성자는 비개발자 출신으로 Flutter 앱과 이 블로그를 주로 Claude Code로 만들었는데, 이 규칙 파일이 결과물의 일관성을 유지하는 데 가장 큰 역할을 했다. 제작 기록은 <Link href="/ko/blog/claude-code-flutter-app-guide">Claude Code + Flutter 앱 가이드</Link>와 <Link href="https://babipanote.com/blog/building-app-with-claude-code">babipanote의 앱 제작 기록</Link>에 남겼다.

모델 선택에 따른 차이는 <Link href="/ko/blog/claude-4-sonnet-vs-gpt-4o">Claude Sonnet 4 vs GPT-4o 비교</Link>에서 다뤘다. 같은 모델이라도 도구가 컨텍스트를 모으는 방식에 따라 결과가 달라진다는 점은 기억해 두자.

## MCP 레이어 — AI가 내 파일과 서비스를 다룬다

[Model Context Protocol(MCP)](https://modelcontextprotocol.io)은 AI 애플리케이션을 외부 데이터·도구에 연결하는 오픈 표준이다. Claude는 물론 ChatGPT, VS Code, Cursor 같은 여러 클라이언트가 지원한다. 연결해 두면 "자료를 복사해 붙여 넣고, 답을 받아 다시 옮기는" 왕복이 줄어든다.

![MCP 3단 레이어 — Claude 클라이언트 ↔ MCP 서버 ↔ 외부 도구](/images/ai-coding-complete-guide-2026/03-mcp-layers.png)
<figcaption style={{ textAlign: "center", fontSize: "0.9rem", color: "#64748b", marginTop: "-0.5rem", marginBottom: "2rem" }}>
  클라이언트가 MCP 서버를 통해 vault·저장소·웹 API를 다룬다
</figcaption>

1인 빌더에게 MCP가 의미 있는 이유는 노트와 코드의 경계가 얇아진다는 점이다. Obsidian에 적어 둔 기획 노트를 AI가 직접 읽어 작업에 반영하고, 끝난 뒤 변경 요약을 같은 노트에 남길 수 있다. 입문은 <Link href="/ko/blog/claude-mcp-guide">Claude MCP 활용법</Link>에, 노트 vault와의 연동은 <Link href="/ko/blog/obsidian-claude-code-mcp">Obsidian × Claude Code MCP 연결</Link>에, 쓸 만한 플러그인은 <Link href="/ko/blog/obsidian-mcp-plugins-best-5">Obsidian MCP 플러그인 BEST 5</Link>에 정리했다.

## 1인 빌더 AI 코딩 워크플로우 6단계

도구를 여러 개 쓸 때는 단계마다 넘겨줄 산출물을 하나로 좁혀 두면 흐름이 끊기지 않는다.

![1인 빌더 AI 코딩 워크플로우 6단계 — 기획부터 회고까지](/images/ai-coding-complete-guide-2026/04-workflow-6steps.png)
<figcaption style={{ textAlign: "center", fontSize: "0.9rem", color: "#64748b", marginTop: "-0.5rem", marginBottom: "2rem" }}>
  Obsidian → Claude Desktop → Claude Code → Cursor → Git → 회고 노트
</figcaption>

1. **기획 — Obsidian**에 spec·결정 사항 정리. 산출물: `spec.md` 1개
2. **설계 — Claude Desktop + MCP**가 spec을 읽고 구조 제안. 산출물: 디렉터리 트리·파일 목록
3. **구현 — Claude Code**가 여러 파일 생성·수정. 산출물: 동작하는 첫 빌드
4. **다듬기 — Cursor**로 컴포넌트별 세부 조정. 산출물: 다듬어진 파일
5. **배포 — Git push → Vercel 자동 빌드**. 산출물: 라이브 URL
6. **회고 — Obsidian**에 변경 요약과 다음 할 일 기록. 산출물: 회고 노트

"단계 사이에 넘기는 산출물을 줄인다"는 원칙은 <Link href="/ko/blog/solo-developer-automation-stack">1인 개발자 자동화 스택 10가지</Link> Pillar에서도 같다. 블로그 운영에 이 흐름을 적용한 사례는 <Link href="/ko/blog/claude-blog-workflow-seo">Claude 블로그 워크플로우</Link>에 있다.

## 처음 셋업 — 30분 순서

1. **Claude Code 설치** — 공식 네이티브 설치가 권장된다. macOS·Linux는 `curl -fsSL https://claude.ai/install.sh | bash`, Windows PowerShell은 `irm https://claude.ai/install.ps1 | iex`. npm(`npm install -g @anthropic-ai/claude-code`)이나 Homebrew로도 설치할 수 있다
2. **프로젝트 루트에 `CLAUDE.md`** — 코드 스타일·디렉터리 규칙·테스트 방법을 5~10줄로
3. **Claude Desktop + MCP 연결** — 노트 vault처럼 자주 쓰는 폴더 하나만 먼저 연결한다
4. **에디터는 필요할 때** — 코드를 보며 고치는 일이 잦아지면 Cursor를 추가한다

지식관리 도구가 아직 없다면 <Link href="/ko/blog/obsidian-getting-started">Obsidian 시작 가이드</Link>로 vault부터 만들고, 다른 노트앱을 쓰고 있다면 <Link href="/ko/blog/notion-alternatives-best-5">Notion 대체 앱 BEST 5</Link>에서 MCP 연결 가능 여부를 확인해 보자.

## 보안 체크리스트

AI에게 파일과 명령 실행을 맡기는 만큼 경계를 정해 두어야 한다.

- [ ] MCP로 연결하는 폴더는 필요한 범위로만 좁힌다 (개인 일기·재무 노트는 별도 vault)
- [ ] `.env`·API 키 파일은 AI가 읽을 수 있는 경로에 두지 않거나 무시 목록에 넣는다
- [ ] 명령 실행 권한은 처음엔 매번 승인으로 두고, 익숙해진 명령만 허용 목록에 넣는다
- [ ] AI가 만든 변경은 커밋 전에 diff로 검토한다
- [ ] 신뢰할 수 없는 MCP 서버는 설치하지 않는다

## 자주 묻는 질문 (FAQ)

### AI 코딩 도구를 여러 개 다 깔아야 하나요?

아닙니다. Claude Code나 Cursor 중 하나로 시작해 `CLAUDE.md` 같은 프로젝트 규칙을 먼저 정리해 보세요. 일주일쯤 써 보면 어떤 단계가 막히는지 보이고, 그때 필요한 도구를 더하면 됩니다. 처음부터 여러 도구를 깔면 흐름만 복잡해집니다.

### 비개발자도 Claude Code를 쓸 수 있나요?

쓸 수 있습니다. 하고 싶은 일을 자연어로 설명하면 됩니다. 다만 결과를 확인할 수 있을 만큼의 도메인 이해와 터미널 기본 명령 몇 개는 필요합니다. 터미널이 부담스럽다면 공식 데스크톱 앱이나 VS Code 확장으로 시작할 수도 있습니다.

### Claude Code는 무료로 쓸 수 있나요?

공식 설치 문서에 따르면 Claude Code는 무료 claude.ai 플랜에 포함되지 않습니다. Pro·Max·Team·Enterprise 구독이나 Console(API) 계정이 필요합니다. 2026년 10월 기준 Pro는 월 20달러이며, API 키로 쓰면 사용한 토큰만큼 과금됩니다.

### MCP는 안전한가요?

MCP 자체는 연결 규격이고, 안전성은 어떤 서버를 어떤 권한으로 연결하느냐에 달려 있습니다. 로컬 서버라도 AI에게 전달된 내용은 모델 제공사로 전송된다는 점을 기억하세요. 연결 폴더를 좁히고, 출처가 확실한 서버만 쓰고, 민감한 자료는 분리하는 것이 기본입니다.

### 한국어로 지시해도 괜찮나요?

괜찮습니다. 다만 코드 주석·커밋 메시지·문서의 언어 규칙을 `CLAUDE.md`나 에디터 규칙 파일에 명시해 두면 결과가 일관됩니다. 품질은 모델과 작업에 따라 다르니 자주 하는 작업으로 직접 확인해 보는 것이 좋습니다.

### 코딩이 본업이 아닌 사람에게도 의미가 있나요?

블로그·콘텐츠 운영에도 코드 작업이 자주 끼어듭니다. 정적 사이트 수정, GitHub Actions 작성, 배포 설정 같은 일입니다. 이런 작업 비중이 있다면 AI 코딩 도구 하나만으로도 시간을 아낄 수 있습니다. 블로그 운영 자동화 사례는 위에서 소개한 블로그 워크플로우 글에 있습니다.

## 마무리 — 도구 선택보다 흐름 설계

AI 코딩에서 중요한 것은 "어느 도구가 가장 좋은가"보다 "도구를 어떤 흐름으로 묶는가"다. 규칙 파일로 일관성을 잡고, MCP로 노트와 코드 사이 왕복을 줄이고, 에디터는 필요할 때 더하는 순서를 권한다. 이 Pillar는 도구 변화에 맞춰 분기마다 갱신한다. 추가로 Cursor 기능은 [Cursor 문서](https://cursor.com/docs)에서 확인할 수 있다.
