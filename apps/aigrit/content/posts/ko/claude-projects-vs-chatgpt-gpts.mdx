## 한 줄 요약

내 자료와 규칙을 미리 넣어 두고 반복해서 쓰는 **맞춤 AI 작업공간**이라는 점은 같다. **Claude Projects**는 *나와 팀이 쓰는 비공개 작업공간*에, **ChatGPT GPTs**는 *링크나 스토어로 남에게 배포하는 어시스턴트*에 맞춰져 있다. 경쟁보다는 용도가 갈리는 도구다.

두 서비스에 들어가는 기본 모델의 스펙 차이는 <Link href="/ko/blog/claude-4-sonnet-vs-gpt-4o">Claude Sonnet 4 vs GPT-4o 비교</Link>에서 따로 다뤘으니, 이 글은 작업공간 기능 자체에 집중한다.

## 핵심 비교

| 항목 | Claude Projects | ChatGPT GPTs |
|------|----------------|--------------|
| **형태** | 대화 기록 + 지식 베이스를 묶은 작업공간 | 지시문·지식·도구를 묶은 맞춤 어시스턴트 |
| **이용 가능** | 무료 포함 모든 사용자 (무료는 5개까지) | GPT 만들기는 유료 플랜 중심 |
| **지식 주입** | 문서·텍스트·코드 업로드, 유료 플랜은 RAG로 용량 확장 | 파일 최대 20개, 파일당 512MB |
| **맞춤 지시** | 프로젝트별 지시 | GPT별 Instructions |
| **외부 연동** | 커넥터·MCP | Actions(API 호출)·내장 도구 |
| **공유** | Team·Enterprise 조직 안에서 공유 (보기·편집 권한) | 링크 공개, GPT Store 등록 |
| **개인 유료** | Claude Pro 월 $20 | ChatGPT Plus 월 $20 |

결정적인 차이는 **공유 범위**다. Projects는 조직 안에서 함께 쓰는 공간이고, GPTs는 조직 밖의 누구에게나 링크로 줄 수 있다.

## 지식 주입 — 무엇을 얼마나 넣을 수 있나

Claude 고객센터에 따르면 Projects에는 문서·텍스트·코드 파일을 지식으로 올릴 수 있고, 유료 플랜에서는 내용이 컨텍스트 한도에 가까워지면 **RAG 모드**로 전환해 용량을 최대 10배까지 늘린다. GPTs는 파일을 최대 20개, 파일당 512MB까지 붙일 수 있다.

어느 쪽이든 결과 품질은 자료 정리에 크게 좌우된다.

- **문서를 주제별로 나눠 올린다** — 한 파일에 모든 내용을 몰아넣지 않기
- **지시문에서 자료의 우선순위를 밝힌다** — "브랜드 가이드가 과거 글보다 우선"처럼
- **근거 문서를 밝히게 한다** — "답변 끝에 참고한 문서 이름을 적어"라고 요청하면 검증이 쉬워진다

자료를 내 노트·파일에서 바로 가져오게 하려면 <Link href="/ko/blog/claude-mcp-guide">Claude MCP 활용법</Link>에서 다룬 외부 연결이 도움이 된다.

## 공유와 배포 — GPTs의 영역

여기서 둘이 갈린다.

- **Claude Projects**: Team·Enterprise 플랜에서 이메일로 개인을 초대하거나 조직 전체에 공개할 수 있다. 권한은 보기와 편집으로 나뉜다. 조직 밖으로 링크를 뿌리는 용도는 아니다
- **ChatGPT GPTs**: 링크로 공개하거나 **GPT Store**에 등록해 검색으로 노출할 수 있다

남이 쓸 도구를 만들어 배포할 생각이라면 GPTs가 맞다. GPT Store로 수익을 기대한다면 빌더 수익 프로그램이 어디까지 열려 있는지 <Link href="/ko/blog/gpt-store-monetization-2026">GPT Store 수익화 현실 2026</Link>에서 먼저 확인하자. 반대로 미공개 원고나 내부 문서처럼 밖으로 나가면 안 되는 자료라면 Projects의 닫힌 구조가 장점이다.

## 외부 연동 — MCP vs Actions

| 항목 | Claude (커넥터·MCP) | ChatGPT GPTs (Actions) |
|------|----------------------|------------------------|
| 연결 방식 | MCP 서버를 커넥터로 연결 | OpenAPI 스키마로 API 연결 |
| 준비물 | 공식·커뮤니티 MCP 서버 또는 직접 만든 서버 | API 명세와 인증 설정 |
| 잘 맞는 일 | 파일·노트앱·DB 읽고 쓰기 | 외부 서비스 API 호출 |

MCP는 노트앱이나 파일처럼 **읽고 쓰는** 연결에, Actions는 정해진 외부 **API를 호출**하는 연결에 직관적이다. 작성자가 노트앱을 AI가 직접 편집하게 만든 사례는 babipanote의 <Link href="https://babipanote.com/blog/claude-mcp-obsidian-live">Claude MCP + Obsidian 연동 기록</Link>에 있다.

## 누가 어느 쪽을 써야 하나

### Claude Projects가 맞는 사람

- **비공개 자료를 반복 참조**하는 사람: 미공개 원고·브랜드 문서·내부 위키
- **팀 안에서 같은 지식과 지시를 공유**하려는 사람 (Team·Enterprise)
- **커넥터·MCP로 자기 도구를 붙이려는** 사람

### ChatGPT GPTs가 맞는 사람

- **남이 쓸 도구를 만드는** 사람: 고객·구독자에게 배포할 어시스턴트
- **GPT Store 노출**을 노리는 사람
- **정해진 API를 호출하는 자동화**를 원하는 사람

맞춤 AI를 판매 상품으로 보는 관점은 <Link href="/ko/blog/sell-ai-prompts-promptbase">AI 프롬프트 판매 시작 가이드</Link>와도 이어진다.

## 자주 묻는 질문 (FAQ)

### Claude Projects와 ChatGPT GPTs를 둘 다 구독해야 하나요?

꼭 그럴 필요는 없습니다. 비공개 자료 기반 반복 작업이 중심이면 Claude 하나로, 남에게 배포할 어시스턴트를 만드는 게 목적이면 ChatGPT 하나로 시작하세요. Claude Projects는 무료 계정에서도 5개까지 만들 수 있어 먼저 시험해 보기 쉽습니다.

### GPTs처럼 Claude Projects도 외부에 공개할 수 있나요?

2026년 10월 Claude 고객센터 기준 Projects 공유는 Team·Enterprise 플랜에서 조직 구성원에게 하는 방식입니다. 이메일로 개인을 초대하거나 조직 전체에 공개할 수 있지만, 조직 밖 누구나 접근하는 링크 배포는 GPTs가 맞습니다.

### 업로드한 자료가 모델 학습에 쓰이나요?

플랜과 설정에 따라 다릅니다. 두 서비스 모두 팀·기업용 플랜은 업무 데이터를 학습에 쓰지 않는다는 정책을 두고 있고, 개인 플랜은 설정에서 학습 사용 여부를 고를 수 있습니다. 민감한 자료라면 각 서비스의 데이터 정책과 설정을 먼저 확인하세요.

### 맞춤 지시는 어디까지 따르나요?

톤·형식·금지어 같은 규칙은 대체로 잘 따르지만, 대화가 길어지면 초반 지시가 약해질 수 있습니다. 중요한 규칙은 지시문 맨 위에 짧고 분명하게 두고, 같은 규칙을 지식 문서에도 한 번 더 적어 두면 안정적입니다.

### 코딩 작업에도 쓸 만한가요?

가벼운 코드 리뷰나 짧은 코드 작성에는 둘 다 쓸 만합니다. 여러 파일을 고치고 명령을 실행하는 작업은 코딩 전용 도구가 낫습니다. 도구별 차이는 <Link href="/ko/blog/claude-code-vs-cursor">Claude Code vs Cursor 비교</Link>를 참고하세요.

## 마무리

Claude Projects와 ChatGPT GPTs는 같은 "맞춤 AI 작업공간"이지만 향하는 방향이 다르다. 안으로 쓰는 비공개 작업이면 Projects, 밖으로 배포하는 어시스턴트라면 GPTs. 전체 AI 도구 선택의 큰 그림은 <Link href="/ko/blog/ai-tools-2026-guide">2026 AI 도구 가이드</Link>에서 이어진다.
