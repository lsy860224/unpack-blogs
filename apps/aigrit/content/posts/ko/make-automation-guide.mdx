**결론부터: Make로 Slack·Notion·Gmail을 연결하면 반복 업무 한 종류를 코드 없이 자동화할 수 있다. 무료 플랜 크레딧이 Zapier 무료 태스크보다 넉넉하고 분기·반복을 시각적으로 다루기 좋지만, 도움말 대부분이 영어라는 점이 진입장벽이다.**

[Make](https://www.make.com)(구 Integromat)는 노드를 이어 붙이는 시각 빌더로 앱 간 데이터를 흐르게 하는 노코드 자동화 도구다. Zapier와 함께 가장 많이 쓰이지만 한국어 자료가 적다. 처음 쓰는 사람이 첫 자동화를 완성하는 경로를 정리한다.

## Make란? 1분 설명

쉽게 말하면 **앱 간 "이런 일이 생기면 저걸 한다" 자동화**다. "Gmail에 특정 키워드 메일이 오면 → Notion DB에 저장 → Slack에 알림" 같은 흐름을 코드 없이 만든다.

| 핵심 개념 | 설명 |
|---|---|
| Scenario | 자동화 한 단위 (워크플로우) |
| Module | 시나리오 안의 노드 (Gmail·Notion 등 앱 동작 1개) |
| Credit | 과금 단위. 모듈이 실행될 때 차감 |
| Connection | 앱 인증 정보 (한 번 연결 후 재사용) |
| Webhook | 외부에서 호출해 즉시 시나리오를 시작하는 트리거 |

Zapier가 단계가 적은 단순 흐름에 강하다면, Make는 **Router·Filter·Iterator·Aggregator 같은 분기·반복 도구**를 시각적으로 다루기 좋다. 그만큼 처음 배울 개념은 더 많다.

## Make와 Zapier 중 어느 쪽을 써야 할까?

![Make vs Zapier — 무료 한도, 과금 단위, 빌더 방식, 분기·반복, 앱 수](/images/make-automation-guide/01-make-vs-zapier.png)

| 항목 | Make | Zapier |
|---|---|---|
| 무료 한도 | 월 1,000 크레딧 | 월 100 태스크, 2단계 Zap |
| 유료 시작 | Core 플랜 (월 10,000 크레딧부터) | Professional 월 $19.99부터 |
| 빌더 방식 | 노드 그래프 | 단계 목록 |
| 분기·반복 | Router·Iterator·Aggregator | Paths 등 (다단계는 유료) |
| 연동 앱 수 (공식 표기) | 3,000개 이상 | 9,000개 이상 |
| 도움말 언어 | 대부분 영어 | 대부분 영어 |

크레딧과 태스크는 세는 방식이 달라 숫자를 그대로 비교하기 어렵다. 다만 무료로 여러 단계짜리 흐름을 시험해 보기에는 Make 쪽이 여유가 있다.

- **단계가 적은 단순 자동화** → Zapier (배우기 쉬움)
- **분기·반복이 많은 흐름** → Make (시각 빌더·무료 여유)
- **월 실행량이 적은 개인 자동화** → Make 무료로 시작

모바일 중심의 가벼운 자동화는 [Apple 단축어로 만드는 AI 자동화 5가지](/ko/blog/apple-shortcuts-ai-automation)가, 1인 작업 전체의 자동화 구성은 [1인 개발자 자동화 스택 10가지](/ko/blog/solo-developer-automation-stack)가 더 맞을 수 있다.

## 가입 & 첫 시나리오 만들기

![Make 시나리오 빌더 흐름 — Trigger → Filter → Action 노드](/images/make-automation-guide/02-scenario-builder.png)

1. make.com 가입 (Google 계정으로 가입하면 이후 연결이 편하다)
2. 좌측 사이드바 → **Scenarios** → **Create a new scenario**
3. 가운데 + 버튼 → **트리거 앱 선택** (예: Gmail)
4. 트리거 모듈 선택 (예: Watch emails)
5. Connection 추가 (앱 로그인·권한 허용)
6. 트리거 조건 설정 (예: 특정 라벨 또는 "invoice" 포함)
7. + 버튼 → 다음 모듈 추가 (예: Notion → Create a database item)
8. 데이터 매핑 (Gmail 제목 → Notion 제목 속성 등)
9. **Run once**로 테스트
10. 스케줄 토글을 켜서 자동 실행

**핵심 팁:** 켜기 전에 Run once로 여러 번 확인하자. 필터를 빠뜨린 채 켜 두면 의도하지 않은 데이터까지 처리하며 크레딧이 빠르게 줄어든다.

## 실전 #1 — 블로그 발행 → Slack 알림

![실전 시나리오 3가지 구성 — RSS→Slack, Gmail→Notion, Sheets→이메일](/images/make-automation-guide/03-real-cases.png)

가장 단순한 시나리오라 첫 연습으로 좋다.

**구성:**
1. RSS 트리거 — 블로그 RSS 피드 감시
2. Slack 모듈 — 채널에 메시지 보내기
3. 메시지 템플릿: `📝 새 글: {title}\n{link}`

**팁:** RSS 트리거의 최대 처리 개수를 1로 두자. 그렇지 않으면 첫 실행에 과거 글을 한꺼번에 처리할 수 있다.

## 실전 #2 — Gmail → Notion DB 자동 저장

뉴스레터를 카테고리별 Notion DB로 모으는 식으로 받은 메일함 정리에 쓴다.

**구성:**
1. Gmail 트리거 — Watch emails (라벨 "Newsletter" 필터)
2. **Filter** — 제목에 특정 키워드가 있는지로 분기
3. Notion 모듈 — Create a database item
4. (선택) Gmail 모듈 — 라벨 변경·보관 처리

**팁:** Notion DB 속성 타입을 미리 맞춰 두자. 제목·URL·태그(다중 선택)·날짜 정도가 무난한 조합이다. DB 구조는 [Notion AI 활용법](/ko/blog/notion-ai-guide)에서 다룬 패턴을 참고하면 된다.

## 실전 #3 — Google Sheets → 이메일 일괄 발송

회원 알림처럼 목록을 돌며 메일을 보내는 시나리오다. 행 수만큼 모듈이 반복 실행되므로 크레딧 소모가 크다.

**구성:**
1. Google Sheets 트리거 — Watch new rows
2. **Iterator** — 행 순회
3. Gmail 모듈 — Send an email (수신자·본문 템플릿)

**팁:** 반복 안에 Sleep 모듈로 간격을 두면 발송 속도 제한에 덜 걸린다. 대량 발송이라면 Gmail보다 전용 메일 발송 서비스가 맞고, 수신 동의와 수신 거부 처리 같은 관련 규정도 지켜야 한다.

## 무료 플랜으로 어디까지 가능할까?

무료 플랜은 월 1,000 크레딧이다. 크레딧은 모듈이 실행될 때마다 차감되므로, **시나리오 1회 실행에 쓰이는 모듈 수 × 월 실행 횟수**로 대략 가늠할 수 있다.

- 모듈 2개짜리 시나리오(RSS → Slack)는 무료 한도 안에서 수백 번 실행할 수 있다
- 반복(Iterator)이 들어가면 항목 수만큼 모듈이 실행돼 소모가 빠르다
- 스케줄 실행 간격을 짧게 잡을수록 확인 횟수가 늘어난다

무료 플랜에는 활성 시나리오 수와 최소 실행 간격에도 제한이 있으니, 세부 한도는 공식 요금 페이지에서 확인하자. 실행량이 늘면 Core 플랜부터 검토하면 된다. 사용량 기반으로 비용을 계산하는 방식은 [Claude Sonnet 4 vs GPT-4o 비교](/ko/blog/claude-4-sonnet-vs-gpt-4o)의 API 비용 계산과 같은 원리다.

## 트러블슈팅 — 자주 만나는 함정 4가지

**1. 필터 누락 → 크레딧 급감**

트리거 바로 뒤에 동작을 연결하고 조건을 걸지 않으면 모든 데이터에 반응한다. 트리거와 동작 사이에 필터를 두는 습관을 들이자.

**2. Webhook 응답이 늦음**

외부 서비스가 Webhook을 호출한 뒤 오래 기다리지 않는 경우가 많다. Webhook response 모듈로 먼저 응답하고, 오래 걸리는 처리는 그 뒤에 두거나 별도 시나리오로 나누자.

**3. Notion API 요청 제한**

Notion API는 평균 초당 3회 수준의 요청 제한이 있다. Iterator로 많은 항목을 한 번에 보내면 일부가 실패할 수 있으니 Sleep 모듈로 간격을 두자.

**4. 응답 데이터 구조가 예상과 다름**

외부 API 응답 구조가 문서와 다를 때가 있다. Run once로 실제 응답을 확인하고, Set multiple variables 모듈로 필요한 값만 꺼내 정리하면 디버깅이 쉽다. AI가 외부 도구와 데이터를 주고받는 다른 방식은 [Claude MCP 활용법](/ko/blog/claude-mcp-guide)에서 다뤘다.

## 자주 묻는 질문 (FAQ)

### Make는 한국어를 지원하나요?

도움말·튜토리얼·오류 메시지는 대부분 영어입니다. 화면 구성이 시각적이라 기본 흐름은 영어가 익숙하지 않아도 따라갈 수 있지만, 오류를 해결할 때는 영어 문서를 읽어야 하는 경우가 많습니다. 브라우저 번역 기능을 함께 쓰면 도움이 됩니다.

### Zapier보다 저렴한가요?

무료 기준으로는 Make가 월 1,000 크레딧, Zapier가 월 100 태스크로 Make 쪽이 넉넉합니다. 다만 두 서비스는 과금 단위를 세는 방식이 달라 단순 비교가 어렵습니다. 내 시나리오의 단계 수와 월 실행 횟수로 각각 계산해 보고 정하세요.

### 코딩 지식이 필요한가요?

기본 자동화에는 필요 없습니다. 날짜 형식 변환이나 텍스트 가공처럼 데이터를 다듬을 때는 Make의 함수와 수식 문법을 조금 익혀야 합니다. 원하는 변환을 설명하고 AI 챗봇에 수식을 물어보면 빠르게 해결되는 경우가 많습니다.

### Webhook을 트리거로 쓰면 즉시 반응하나요?

네. Webhook 트리거는 외부에서 Make의 Webhook URL로 요청을 보내는 순간 시나리오가 시작됩니다. 반면 RSS나 Gmail 감시처럼 주기적으로 확인하는 트리거는 설정한 실행 간격만큼 지연이 생깁니다. 실시간에 가까운 자동화가 필요하면 Webhook을 쓰세요.

### 무료 플랜에서 시나리오는 몇 개까지 만들 수 있나요?

시나리오는 여러 개 만들 수 있지만, 무료 플랜은 동시에 켜 둘 수 있는 활성 시나리오 수가 제한됩니다. 자주 쓰지 않는 시나리오는 꺼 두고 필요할 때만 켜는 방식으로 운영하세요. 정확한 한도는 Make 요금 페이지에서 확인할 수 있습니다.

## 총정리

자동화 도구 선택은 "분기·반복이 얼마나 자주 필요한가"가 기준이다. 단순한 흐름은 Zapier, 분기·반복이 많은 흐름은 Make. 실행량이 적다면 Make 무료로 시작해 크레딧이 부족해질 때 유료 플랜을 검토하는 순서가 무난하다. 자동화 도구를 포함한 더 넓은 지형도는 [2026 AI 도구 가이드](/ko/blog/ai-tools-2026-guide)에 정리했다.
