## 한 줄 요약

**Claude Agent SDK**는 Claude Code를 움직이는 도구·에이전트 루프·컨텍스트 관리를 Python과 TypeScript 라이브러리로 쓰게 해 준다. 첫 에이전트는 세 단계면 돈다 — 패키지 설치 → 커스텀 **툴 정의** → `query`로 에이전트 **루프** 실행. 이 글은 공식 문서의 예제 구조를 따라 TypeScript와 Python 코드를 나란히 놓고, 툴 하나짜리 에이전트를 만든 뒤 배포까지의 흐름을 정리한다.

<Callout type="info" title="실습 환경">
  대상: Node.js 18+ 또는 Python 3.10+ · 패키지: `@anthropic-ai/claude-agent-sdk`(TS) / `claude-agent-sdk`(Python) · 사전 준비: Anthropic API 키 · 예제: 좌표를 받아 현재 기온을 돌려주는 커스텀 툴 1개. 코드는 2026년 10월 [Agent SDK 공식 문서](https://code.claude.com/docs/en/agent-sdk/overview) 기준이며, API는 바뀔 수 있으니 실행 전 문서를 함께 확인하자.
</Callout>

이 글은 에이전트가 *무엇인지*는 이미 안다고 가정한다. 정의·구조·도구 비교가 궁금하다면 먼저 <Link href="/ko/blog/ai-agent-complete-guide-2026">AI 에이전트 완벽 가이드 2026</Link>을 읽고 오는 편이 좋다. 여기서는 그 가이드의 4요소 중 *툴 호출과 루프*를 코드로 직접 구현한다.

## Claude Agent SDK는 어디에 쓰나

Anthropic 문서는 Claude로 에이전트를 만드는 길을 네 갈래로 나눈다. 차이는 *누가 에이전트를 실행하고, 무엇이 기본으로 들어 있느냐*다.

![Claude로 에이전트를 만드는 네 가지 방법 — Agent SDK·Client SDK·Managed Agents·Claude Code CLI](/images/claude-agent-sdk-getting-started/01-overview.png)

| 하고 싶은 일 | 쓸 것 | 얻는 것 |
|------|------|------|
| 내 Python·TS 앱 안에 에이전트를 넣고 직접 운영 | **Agent SDK** | Claude Code의 내장 도구·권한·세션·훅을 라이브러리로 |
| Claude API를 코드에서 직접 호출 | **Client SDK** | 툴 루프는 직접 짜거나 베타 tool runner 사용 |
| 에이전트 실행을 Anthropic에 맡김 | **Managed Agents** | Anthropic이 호스팅하는 에이전트 실행 환경 |
| 터미널에서 대화하며 개발 | **Claude Code CLI** | 일상 개발용 터미널 인터페이스 |

출처: [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview). 툴 호출 루프를 직접 구현하지 않고, 파일 읽기·명령 실행 같은 내장 도구와 MCP·서브에이전트를 그대로 쓰고 싶다면 Agent SDK가 맞다. 코딩 에이전트 도구 자체를 비교한 글은 <Link href="/ko/blog/claude-code-vs-cursor">Claude Code vs Cursor 비교</Link>에 있다.

## Step 1 — 설치와 API 키

SDK를 설치하고 API 키를 환경변수로 등록한다. 공식 문서에 따르면 두 SDK 모두 Claude Code 실행 파일을 함께 설치하므로 대부분 별도 설치가 필요 없다.

```bash
# TypeScript
npm install @anthropic-ai/claude-agent-sdk zod
npm install --save-dev tsx

# Python
pip install claude-agent-sdk httpx

# API 키 등록 (공통)
export ANTHROPIC_API_KEY=your-api-key
```

API 키는 [Claude Console](https://platform.claude.com/)에서 발급한다. SDK는 `.env` 파일을 자동으로 읽지 않으니, 실행하는 셸의 환경변수로 넣거나 직접 불러와야 한다. 키를 코드에 직접 쓰지 않는 것이 기본이다.

## Step 2 — 커스텀 툴 정의하기

에이전트가 외부 세계와 만나는 통로가 **툴**이다. 좌표를 받아 현재 기온을 돌려주는 `get_weather` 툴을 정의하고, 앱 안에서 도는 in-process MCP 서버로 묶는다. TypeScript는 [Zod](https://zod.dev)로 입력 스키마를 정의한다.

```typescript
// weather.ts
import { query, tool, createSdkMcpServer } from "@anthropic-ai/claude-agent-sdk";
import { z } from "zod";

const getWeather = tool(
  "get_weather",
  "좌표로 현재 기온을 조회한다",
  {
    latitude: z.number().describe("위도"),
    longitude: z.number().describe("경도"),
  },
  async (args) => {
    const res = await fetch(
      `https://api.open-meteo.com/v1/forecast?latitude=${args.latitude}&longitude=${args.longitude}&current=temperature_2m`
    );
    const data = (await res.json()) as { current: { temperature_2m: number } };
    return {
      content: [{ type: "text", text: `현재 기온: ${data.current.temperature_2m}°C` }],
    };
  }
);

// 커스텀 툴을 in-process MCP 서버로 묶는다
const weatherServer = createSdkMcpServer({
  name: "weather",
  version: "1.0.0",
  tools: [getWeather],
});
```

Python도 구조가 같다. `@tool` 데코레이터로 이름·설명·입력 스키마를 붙이고, `create_sdk_mcp_server`로 묶는다.

```python
# weather.py
from typing import Any
import httpx
from claude_agent_sdk import tool, create_sdk_mcp_server

@tool("get_weather", "좌표로 현재 기온을 조회한다", {"latitude": float, "longitude": float})
async def get_weather(args: dict[str, Any]) -> dict[str, Any]:
    async with httpx.AsyncClient() as client:
        res = await client.get(
            "https://api.open-meteo.com/v1/forecast",
            params={
                "latitude": args["latitude"],
                "longitude": args["longitude"],
                "current": "temperature_2m",
            },
        )
        data = res.json()
    return {"content": [{"type": "text", "text": f"현재 기온: {data['current']['temperature_2m']}°C"}]}

weather_server = create_sdk_mcp_server(name="weather", version="1.0.0", tools=[get_weather])
```

툴 핸들러는 `content` 배열을 가진 객체를 돌려줘야 한다. 이 값이 모델이 읽는 *관찰 결과*가 된다. 실패를 알릴 때는 `isError: true`(Python은 `"is_error": True`)를 함께 돌려주면 모델이 오류 메시지를 읽고 다른 방법을 시도한다. 툴을 MCP로 노출하는 개념은 <Link href="/ko/blog/claude-mcp-guide">Claude MCP 활용법</Link>에서 더 볼 수 있다.

## Step 3 — 에이전트 루프 실행하기

이제 툴을 에이전트에게 넘기고 목표를 던진다. `query`가 *계획 → 툴 호출 → 관찰 → 판단* 루프를 내부에서 돈다. 툴 이름은 `mcp__{서버 키}__{툴 이름}` 형식이다.

```typescript
// weather.ts (이어서)
for await (const message of query({
  prompt: "서울 날씨 알려줘",
  options: {
    mcpServers: { weather: weatherServer },
    allowedTools: ["mcp__weather__get_weather"], // 승인 없이 실행할 툴
    tools: [], // 파일·셸 같은 내장 도구는 이 예제에서 뺀다
    maxTurns: 3, // 루프 반복 상한
  },
})) {
  if (message.type === "result" && message.subtype === "success") {
    console.log(message.result);
  }
}
```

`npx tsx weather.ts`로 실행한다. 모델은 "서울 날씨"를 받아 서울의 좌표를 스스로 채워 `get_weather`를 호출하고, 돌아온 기온을 읽어 답을 만든다. 사용자가 좌표를 준 적이 없어도 계획 단계에서 채운다는 점이 단발 응답과 다르다.

옵션 두 가지는 꼭 구분하자. `allowedTools`는 *승인 없이 실행할 툴 목록*일 뿐 Claude를 그 툴로 제한하지 않는다. 목록에 없는 툴은 권한 모드에 따라 처리된다. 내장 도구 자체를 빼려면 `tools`를 쓴다. `maxTurns`는 툴 호출 왕복 횟수의 상한으로, 비용 관리의 첫 손잡이다.

Python은 같은 `query`를 `ClaudeAgentOptions`와 함께 쓴다.

```python
# weather.py (이어서)
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage

async def main():
    options = ClaudeAgentOptions(
        mcp_servers={"weather": weather_server},
        allowed_tools=["mcp__weather__get_weather"],
        tools=[],
        max_turns=3,
    )
    async for message in query(prompt="서울 날씨 알려줘", options=options):
        if isinstance(message, ResultMessage) and message.subtype == "success":
            print(message.result)

asyncio.run(main())
```

대화를 여러 번 이어 가야 한다면 `ClaudeSDKClient`로 세션을 열어 쓰는 방식도 있다.

## 설치부터 배포까지 — 전체 파이프라인

여기까지가 *동작하는 에이전트*다. 이를 실제 서비스로 올리려면 네 단계의 흐름을 거친다.

![Claude Agent SDK 파이프라인 — 환경 설정·툴 정의·에이전트 루프·배포 4단계](/images/claude-agent-sdk-getting-started/02-pipeline.png)

| 단계 | 핵심 작업 | 체크포인트 |
|------|----------|-----------|
| **1. 설정** | SDK 설치·API 키 환경변수 | 키는 코드에 박지 않는다 |
| **2. 툴 정의** | `tool()` + in-process MCP 서버 | `content` 형식, 오류는 `isError` |
| **3. 루프** | `query` 실행 | `tools`·`allowedTools`·`maxTurns` 구분 |
| **4. 배포** | 서버리스·컨테이너 | 키는 시크릿으로 주입 |

배포 단계에서 피해야 할 실수는 API 키를 빌드 산출물에 포함하는 것이다. 키는 시크릿으로 런타임에 주입하고, 에이전트가 *쓰기*를 하는 툴(파일·결제·메일)에는 권한을 최소로 묶는다. Agent SDK는 Claude Code 실행 파일을 띄우는 구조라, 컨테이너·서버처럼 프로세스를 실행할 수 있는 환경이 필요하다. 배포 방식은 공식 [Hosting 문서](https://code.claude.com/docs/en/agent-sdk/hosting)를 참고하자. 또 Anthropic은 사전 승인 없이 제3자 제품에서 claude.ai 로그인을 제공하는 것을 허용하지 않으므로, 서비스에는 API 키 인증을 쓴다.

## 다음 단계 — 메모리와 멀티에이전트

툴 하나짜리 에이전트가 돌면 절반은 끝난 셈이다. 여기서 작업이 길어지면 **메모리**(이전 결정을 외부 DB에 저장), 역할이 나뉘면 **멀티에이전트**(서브에이전트로 분담)를 붙인다.

![툴 하나가 돈 다음 무엇부터 붙일지 — 메모리·멀티에이전트 확장 결정 흐름](/images/claude-agent-sdk-getting-started/03-flow.png)

Agent SDK에는 세션 유지와 서브에이전트 기능이 들어 있어 이 확장을 같은 라이브러리 안에서 시작할 수 있다. 이 확장 구조의 큰 그림은 **AI 에이전트 완벽 가이드**의 4요소(툴 호출·메모리·멀티에이전트·MCP)로 정리했다. 노트 기반 메모리를 실제로 붙이는 예는 <Link href="/ko/blog/obsidian-claude-code-mcp">Obsidian + Claude Code MCP 연동</Link>에서, 1인 운영자가 에이전트를 자동화 스택에 끼워 넣는 법은 <Link href="/ko/blog/solo-developer-automation-stack">1인 개발자 자동화 스택</Link>에서 이어진다.

## 자주 묻는 질문 (FAQ)

### Claude Agent SDK는 TypeScript와 Python 중 무엇을 써야 하나요?

기존 코드베이스의 언어를 따르는 것이 가장 합리적입니다. 웹 서비스 중심이라면 TypeScript, 데이터 처리 파이프라인 중심이라면 Python이 자연스럽습니다. 두 SDK는 툴 정의와 `query` 실행 구조가 거의 같아 한쪽을 익히면 다른 쪽으로 옮기기 쉽습니다. 입문용이라면 익숙한 언어를 고르면 됩니다.

### allowedTools에 넣지 않은 툴은 어떻게 되나요?

`allowedTools`는 승인 없이 바로 실행할 툴을 정하는 목록이고, Claude가 쓸 수 있는 툴을 그 목록으로 제한하지는 않습니다. 목록에 없는 툴은 권한 모드와 승인 흐름을 거칩니다. 특정 내장 도구를 아예 쓰지 못하게 하려면 `tools` 옵션에서 빼거나 `disallowedTools`에 이름을 넣으세요. 쓰기·삭제처럼 위험한 툴은 자동 승인 목록에 넣지 않는 편이 안전합니다.

### 에이전트가 너무 오래 돌면 어떻게 막나요?

`maxTurns`(Python은 `max_turns`)로 툴 호출 왕복 횟수의 상한을 두는 것이 가장 직접적인 방법입니다. 처음에는 3~5 정도로 낮게 두고 동작을 본 뒤 늘리세요. 툴 설명을 명확히 써서 모델이 불필요하게 재시도하지 않게 하고, 외부 API를 부르는 툴에는 타임아웃과 오류 처리를 넣어 한 곳에서 막히지 않게 합니다.

### 만든 에이전트는 어디에 배포하나요?

Agent SDK는 Claude Code 실행 파일을 띄워 동작하므로, 컨테이너나 서버처럼 프로세스를 실행할 수 있는 환경이 필요합니다. API 키는 빌드 산출물에 넣지 말고 시크릿으로 런타임에 주입하세요. 에이전트가 외부 시스템에 쓰기를 한다면 권한을 최소 범위로 묶고, 호출량과 비용을 기록하는 로깅을 함께 붙이면 운영이 안정적입니다.

## 마무리

첫 자율 에이전트는 거창하지 않아도 된다. 툴 하나, 루프 한 번이면 *스스로 계획하고 행동하는* 에이전트의 본질을 손으로 확인할 수 있다. 이 글의 `get_weather` 예제를 자기 도메인의 툴로 바꿔 끼우는 순간, 같은 골격이 리서치·코딩·운영 어디에나 적용된다. 작게 시작해 루프 하나를 완성하는 것, 그것이 자율 에이전트로 가는 가장 빠른 길이다.
