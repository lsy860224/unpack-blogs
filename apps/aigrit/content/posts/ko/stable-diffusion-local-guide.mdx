## 한 줄 요약

클라우드 이미지 생성기는 편하지만 *사용량 과금, 플랫폼 정책, 구도 통제의 한계*가 따른다. **Stable Diffusion** 계열 모델을 내 PC에서 직접 돌리면 생성 횟수 걱정 없이 실험하고, **ControlNet**으로 구도를, **LoRA**로 화풍을 정밀하게 다룰 수 있다. 이 글은 실행 도구 선택 → 환경 확인 → ControlNet·LoRA 활용 → 라이선스 확인 순서로 정리한다.

<Callout type="info" title="이 글의 기준">
  실행 도구·지원 환경은 ComfyUI·AUTOMATIC1111 GitHub 저장소, 라이선스는 Stability AI 공식 라이선스 페이지(2026년 10월 확인) 기준이다. 필요한 VRAM과 생성 속도는 모델·해상도·설정에 따라 크게 달라지므로, 수치 대신 경향으로 적었다.
</Callout>

로컬 설치를 망설이는 이유는 대개 "내 컴퓨터가 받쳐 줄까"와 "설치가 복잡하지 않을까" 둘이다. 2026년 기준으로는 설치 프로그램이 있는 실행 도구가 생겨 진입 장벽이 꽤 낮아졌다. 클라우드 도구를 포함한 전체 지형은 <Link href="/ko/blog/ai-design-tools-complete-guide-2026">AI 디자인 도구 완벽 가이드</Link>에 정리했고, 이 글은 *로컬로 직접 돌리는* 한 갈래에 집중한다.

## 왜 로컬인가 — 클라우드와 무엇이 다른가

![로컬 Stable Diffusion vs 클라우드 생성기 — 비용, 구도 제어, 화풍, 데이터, 진입 난이도](/images/stable-diffusion-local-guide/01-overview.png)

| 항목 | 로컬 Stable Diffusion 계열 | 클라우드 생성기 |
|------|----------------------|----------------|
| **생성 비용** | 장비·전기료, 횟수 제한 없음 | 구독·크레딧 과금 |
| **구도 제어** | ControlNet으로 입력 이미지 기반 고정 | 주로 프롬프트에 의존 |
| **화풍** | LoRA·체크포인트 교체 | 플랫폼이 제공하는 범위 |
| **이용 정책** | 모델 라이선스·이용 정책 적용 | 플랫폼 정책 적용 |
| **데이터** | 내 PC에만 남음 | 서버로 전송 |
| **진입 난이도** | 중간 (환경·모델 파일 관리) | 낮음 (가입 즉시) |

핵심은 **ControlNet과 LoRA**다. 클라우드에서 "구도는 이렇게, 화풍은 저렇게"를 프롬프트만으로 맞추는 건 운에 가깝지만, 로컬에서는 *포즈·윤곽선·깊이를 입력으로 고정*하고 화풍을 LoRA로 갈아 끼울 수 있다. 반대로 이미지 속 글자나 빠른 시안이 중요하면 <Link href="/ko/blog/midjourney-vs-dalle-vs-ideogram-2026">Midjourney vs DALL·E vs Ideogram 비교</Link>의 클라우드 도구가 여전히 편하다.

## 1단계 — 실행 도구 고르기

![Stable Diffusion 실행 도구 비교 — ComfyUI, AUTOMATIC1111, Forge](/images/stable-diffusion-local-guide/02-webui.png)

Stable Diffusion은 *모델*이고, 실제로 다루는 건 모델을 불러 이미지를 만드는 *실행 도구*다.

| 실행 도구 | 특징 | 2026년 10월 상황 | 적합 대상 |
|------|------|------|----------|
| **[ComfyUI](https://github.com/comfyanonymous/ComfyUI)** | 노드 그래프로 흐름을 짜고 저장·재현 | Windows·macOS 데스크톱 앱 제공, 약 2주마다 안정 버전 | 새로 시작하는 사람, 재현성이 필요한 작업 |
| **[AUTOMATIC1111](https://github.com/AUTOMATIC1111/stable-diffusion-webui)** | 탭 기반 웹UI, 튜토리얼·확장이 많음 | 최신 릴리스 1.10.1 이후 업데이트가 뜸함 | 기존 자료를 따라 하려는 사람 |
| **Forge** | AUTOMATIC1111 기반 포크, 메모리 최적화 | 저장소에서 업데이트 상황 확인 | A1111 화면에 익숙한 사람 |

새로 시작한다면 **ComfyUI**가 무난하다. 데스크톱 앱으로 설치가 간단해졌고, 저장소 기준으로 SD 1.5·SDXL·SD 3.5·FLUX 같은 이미지 모델과 영상·오디오 모델까지 지원 범위가 넓다. 노드 방식이 처음엔 낯설지만, 남이 만든 워크플로우 파일을 불러와 바로 쓸 수 있어 생각보다 진입이 쉽다. AUTOMATIC1111은 관련 자료가 가장 많지만 업데이트가 뜸해 최신 모델 지원은 확인이 필요하다.

## 2단계 — 내 환경 확인하기

가장 먼저 볼 것은 GPU 메모리(VRAM)와 운영체제다.

| 환경 | 확인할 것 |
|------|------|
| **NVIDIA GPU (Windows·Linux)** | 가장 자료가 많은 환경. VRAM이 클수록 고해상도·대형 모델·ControlNet 중첩이 쾌적 |
| **AMD GPU** | ComfyUI 기준 Linux ROCm, Windows는 지원 세대(RDNA 2~4) 확인 |
| **Apple Silicon Mac (M1~M4)** | ComfyUI가 지원. NVIDIA 환경보다 느릴 수 있어 작은 모델부터 |
| **Intel Arc GPU** | ComfyUI가 PyTorch XPU로 지원 |
| **GPU 없음 (CPU만)** | 실행은 되지만 매우 느려 실용성이 낮음 |

경향만 정리하면, SD 1.5 계열은 비교적 적은 VRAM으로도 돌아가고 SDXL·SD 3.5·FLUX 같은 최신·대형 모델은 더 많은 메모리를 원한다. ComfyUI는 가중치를 나눠 불러오는 방식으로 큰 모델도 적은 VRAM에서 돌릴 수 있다고 안내하지만, 그만큼 속도는 느려진다. 처음에는 가벼운 모델로 흐름을 익히고 필요할 때 큰 모델로 옮기자.

설치 흐름은 ComfyUI 데스크톱 앱 기준으로 *앱 설치 → 모델 파일(체크포인트)을 지정 폴더에 넣기 → 기본 워크플로우로 첫 이미지 생성* 순서다. 모델 파일은 출처가 분명한 공식 배포처에서 받고, 받은 파일의 라이선스를 함께 저장해 두자.

## 3단계 — ControlNet으로 구도를 고정한다

ControlNet은 로컬의 가장 큰 무기다. *포즈·윤곽선·깊이·러프 스케치*를 입력으로 주면, 그 구조를 유지한 채 생성한다. 같은 포즈로 여러 화풍을 뽑거나, 손 스케치를 완성 이미지로 바꾸는 작업이 가능해진다.

| 전처리기 | 입력으로 고정하는 것 | 대표 용도 |
|---------|--------------------|----------|
| **OpenPose** | 인물 포즈·골격 | 같은 자세, 다른 인물·화풍 |
| **Canny** | 윤곽선 | 선을 유지한 채 채색·리터치 |
| **Depth** | 깊이·원근 | 공간 구조 유지 |
| **Scribble** | 러프 스케치 | 러프 → 완성 이미지 |
| **Tile** | 세부 묘사 | 고해상도 업스케일 보강 |

ControlNet 모델은 *기반 모델 계열에 맞는 것*을 써야 한다. SD 1.5용과 SDXL용은 서로 호환되지 않는다. 강도(weight)를 낮추면 느슨한 가이드, 높이면 입력에 강하게 고정된다. 구도를 프롬프트의 운이 아니라 *입력 이미지로 결정*할 수 있다는 점이 클라우드와 가장 다른 지점이다.

## 4단계 — LoRA로 화풍·캐릭터를 입힌다

LoRA(Low-Rank Adaptation)는 특정 화풍·캐릭터·사물을 작은 파일로 학습해 기반 모델에 덧붙이는 방식이다. 큰 체크포인트 전체를 바꾸지 않고 LoRA만 바꿔 끼워 화풍을 더한다.

- **화풍 LoRA**: 특정 일러스트·사진 스타일을 일관되게 적용
- **캐릭터 LoRA**: 같은 인물·마스코트를 여러 장면에서 재현
- **개념 LoRA**: 특정 의상·구도·사물을 안정적으로 등장

AUTOMATIC1111 계열은 프롬프트에 `<lora:이름:0.7>`처럼 호출하고, ComfyUI는 LoRA 불러오기 노드를 연결해 강도를 조절한다. 여러 LoRA를 겹칠 수도 있지만 강도가 높으면 서로 충돌하기 쉽다. 썸네일·배너처럼 *같은 화풍을 반복*해야 하는 작업이라면 LoRA가 특히 유용하며, 그런 반복 제작 흐름은 <Link href="/ko/blog/ai-thumbnail-generation-workflow">AI 썸네일 제작 워크플로우</Link>와도 이어진다.

## 5단계 — 라이선스부터 확인한다

로컬에서 만들었다고 해서 마음대로 써도 되는 것은 아니다. *기반 모델, 체크포인트, LoRA마다 라이선스가 따로* 있다.

- **SD 3.5 계열** — [Stability AI Community License](https://stability.ai/license) 기준, 연 매출 100만 달러 미만의 개인·기업은 상업 이용이 무료이고, 그 이상은 Enterprise 라이선스가 필요하다. 생성물의 소유권은 이용 정책 범위 안에서 사용자에게 있다
- **커뮤니티 체크포인트·LoRA** — 배포자가 붙인 조건(상업 이용 금지, 출처 표기 등)을 따로 확인해야 한다
- **특정 작가·실존 인물·유명 캐릭터를 모방한 LoRA** — 저작권·초상권 문제가 생길 수 있어 상업 용도에서는 피하는 편이 안전하다

생성 이미지를 스톡 사이트에 판매하려 한다면 플랫폼의 생성형 AI 규정도 따로 확인해야 한다. Adobe Stock 기준은 <Link href="/ko/blog/ai-image-stock-adobe-midjourney">AI 이미지 스톡 판매 가이드</Link>에 정리했다.

## 정리 — 정밀 작업은 로컬, 빠른 시안은 클라우드

![로컬 도입 판단 기준 — 구도·화풍 통제, 생성량, 장비, 이미지 속 글자](/images/stable-diffusion-local-guide/03-flow.png)

- **구도·화풍을 정밀하게 통제해야 하는가?** → ControlNet·LoRA가 있는 로컬
- **생성량이 많아 과금이 부담되는가?** → 횟수 제한이 없는 로컬
- **GPU가 약하거나 바로 결과가 필요한가?** → 클라우드 생성기
- **이미지 속 글자가 중요한가?** → 텍스트에 강한 클라우드 도구 (<Link href="/ko/blog/ideogram-vs-recraft-text-image">Ideogram vs Recraft 비교</Link>)

로컬의 가치는 *횟수 제한 없는 실험, 정밀 제어, 데이터가 내 PC에 남는다는 점*의 결합이다. 처음 설치와 모델 관리에 드는 수고만 감수하면, 클라우드와 병행하며 *정밀 작업은 로컬, 빠른 시안은 클라우드*로 나눠 쓰는 구성이 현실적이다.

## 자주 묻는 질문 (FAQ)

### Stable Diffusion 로컬 설치에 GPU가 꼭 필요한가요?

사실상 필요합니다. CPU만으로도 실행은 되지만 생성이 매우 느려 실용성이 낮습니다. NVIDIA GPU가 가장 자료가 많고, ComfyUI 기준으로 AMD·Intel Arc·Apple Silicon Mac도 지원합니다. 필요한 메모리는 모델과 해상도에 따라 다르므로, 가벼운 모델로 시작해 보고 필요할 때 큰 모델로 옮기세요.

### Mac에서도 쓸 수 있나요?

네. ComfyUI는 M1~M4 칩의 Apple Silicon Mac을 지원하고 macOS용 데스크톱 앱도 제공합니다. 다만 같은 모델이라도 NVIDIA GPU 환경보다 느릴 수 있으니, SD 1.5 계열처럼 가벼운 모델로 먼저 흐름을 익히는 편이 좋습니다. 큰 모델은 통합 메모리 용량을 확인하고 시도하세요.

### AUTOMATIC1111과 ComfyUI 중 무엇을 골라야 하나요?

새로 시작한다면 ComfyUI를 권합니다. 데스크톱 앱으로 설치가 쉬워졌고, 업데이트가 꾸준하며 최신 모델 지원도 넓습니다. AUTOMATIC1111은 튜토리얼과 확장이 많아 기존 자료를 따라 하기 좋지만, 최신 릴리스 이후 업데이트가 뜸해 새 모델 지원은 확인이 필요합니다.

### 로컬에서 만든 이미지를 상업적으로 써도 되나요?

모델과 LoRA의 라이선스에 따라 다릅니다. SD 3.5 계열은 Stability AI Community License에서 연 매출 100만 달러 미만이면 상업 이용이 무료이고, 그 이상이면 Enterprise 라이선스가 필요합니다. 커뮤니티 체크포인트와 LoRA는 배포자 조건을 따로 확인하고, 특정 작가나 실존 인물을 모방한 모델은 상업 용도에서 피하세요.

## 마무리

로컬 Stable Diffusion은 클라우드 생성기가 주기 어려운 *횟수 제한 없는 실험과 정밀 제어*를 준다. 실행 도구를 고르고, 내 환경을 확인하고, ControlNet으로 구도를 잡고 LoRA로 화풍을 입히는 흐름을 익히되, 상업 이용 전에는 라이선스를 꼭 확인하자. 클라우드 쪽 디자인 도구 후보는 <Link href="/ko/blog/canva-ai-vs-firefly-vs-recraft">Canva AI vs Firefly vs Recraft 비교</Link>에서 이어서 볼 수 있다.
