## 한 줄 요약

**[n8n](https://n8n.io)** 은 단순 트리거→액션 자동화를 넘어, LLM이 *스스로 판단하고 도구를 호출하는* 에이전트 워크플로우를 노코드에 가깝게 짤 수 있는 도구다. 핵심은 **AI Agent 노드**와 **외부 API 노드(HTTP·Gmail·Slack 등)**를 한 캔버스에 묶는 것이다. 이 글은 실제로 돌아가는 다섯 가지 레시피를 골격과 함께 정리한다.

n8n을 단순 "Zapier 대체재"로만 쓰면 절반만 쓰는 것이다. **AI Agent 노드**가 들어오면서 n8n은 *LLM이 도구 목록을 받고 목표에 맞춰 스스로 호출 순서를 정하는* 구조까지 짤 수 있게 됐다. 에이전트가 정확히 무엇인지, 챗봇과 어떻게 다른지는 <Link href="/ko/blog/ai-agent-complete-guide-2026">AI 에이전트 완벽 가이드</Link>에서 개념을 먼저 잡고 오면 이 글의 레시피가 훨씬 선명해진다.

## n8n AI 에이전트의 골격 — 6단계 파이프라인

레시피가 다섯이라도 뼈대는 하나다. 모든 n8n AI 워크플로우는 아래 6단계 흐름으로 환원된다.

![n8n AI 에이전트 워크플로우 6단계 골격 — 트리거에서 자율 액션까지](/images/n8n-ai-agent-workflows/03-pipeline.png)

1. **트리거** — Gmail Trigger·Webhook·Schedule 중 하나로 흐름 시작
2. **입력 정규화** — 본문·메타데이터를 LLM이 읽기 좋은 형태로 정리
3. **AI Agent 노드** — 시스템 프롬프트 + LLM + 도구 목록 연결
4. **Tool 호출** — HTTP Request·DB·검색 노드를 에이전트의 손발로 연결
5. **결과 분기** — If·Switch로 LLM 판단에 따라 경로 분기
6. **외부 액션** — Notion 저장·Slack 알림·Gmail 답장 등 실제 동작

이 골격에서 *어떤 트리거*와 *어떤 도구*를 끼우느냐에 따라 레시피가 갈린다. 단계별로 만드는 감각은 단일 도구를 깊게 다룬 <Link href="/ko/blog/make-automation-guide">Make 자동화 사용법</Link>의 노드 그래프 적응 과정과 거의 같다.

## 레시피 5종 개요 — 무엇을 자동화하나

![n8n AI 에이전트 레시피 5종 개요 — 트리거·LLM 노드·외부 API·자율성 비교](/images/n8n-ai-agent-workflows/01-overview.png)

| 레시피 | 트리거 | 핵심 LLM 노드 | 외부 API | 자율성 |
|------|------|------|------|:---:|
| **메일 분류·답장 초안** | Gmail Trigger | AI Agent | Gmail·Notion | 중 |
| **리서치 요약 봇** | Schedule | Basic LLM Chain | HTTP·Slack | 중 |
| **고객문의 자동 분기** | Webhook | AI Agent + Tool | CRM·Slack | 상 |
| **콘텐츠 파이프라인** | Schedule | Chain×3 | WordPress·이미지 | 상 |
| **데이터 모니터링 알림** | Schedule | AI Agent | HTTP·Telegram | 중 |

다섯 레시피는 모두 위 6단계 골격의 변주다. *자율성 "상"*은 LLM이 도구 호출 순서를 스스로 정하는 진짜 에이전트, *"중"*은 LLM이 판단·요약만 하고 분기는 사람이 설계한 흐름이다.

## 레시피 1 — 메일 분류·답장 초안

**Gmail Trigger**로 특정 라벨 메일이 도착하면, **AI Agent 노드**가 본문을 읽고 카테고리(문의·청구·스팸)를 분류한 뒤 답장 초안을 생성해 Gmail 임시보관함에 저장한다.

- **트리거**: Gmail Trigger (라벨 필터)
- **에이전트 도구**: Notion(과거 답변 검색), Gmail(초안 작성)
- **시스템 프롬프트 핵심**: "고객 톤 유지, 확정 답변 금지, 초안만 작성"

이 레시피의 응답 톤·트리거 설계는 단일 LLM 트리거 패턴을 코드로 다룬 <Link href="/ko/blog/claude-agent-sdk-getting-started">Claude Agent SDK 입문</Link>의 시스템 프롬프트 구조를 노코드로 옮긴 것에 가깝다. 코드를 짜기 부담스러운 사람에게 n8n이 같은 결과의 진입로가 된다.

## 레시피 2 — 리서치 요약 봇

매일 아침 **Schedule 트리거**로 지정 키워드 뉴스·RSS를 HTTP Request로 긁어와, **Basic LLM Chain**이 핵심 3줄로 요약하고 Slack 채널에 카드로 던진다.

- **트리거**: Schedule (매일 08:00)
- **외부 API**: HTTP Request(피드 수집), Slack(전송)
- **LLM 역할**: 다건 입력 → 중복 제거 → 우선순위 3건 요약

여기서 LLM은 도구를 스스로 부르지 않고 *요약만* 하므로 AI Agent 대신 가벼운 Basic LLM Chain으로 충분하다. 자율성을 더 올리려면 "관련 링크를 추가 검색하라"는 도구를 붙여 Agent로 승격하면 된다.

## 레시피 3 — 고객문의 자동 분기

**Webhook 트리거**로 사이트 문의 폼이 들어오면, **AI Agent + Tool** 조합이 문의 유형을 판단하고 *스스로* CRM 조회·담당자 라우팅·1차 답변까지 처리한다. 다섯 레시피 중 자율성이 가장 높다.

| 단계 | 노드 | 역할 |
|------|------|------|
| 수신 | Webhook | 폼 데이터 수신 |
| 판단 | AI Agent | 유형 분류 + 긴급도 산정 |
| 도구 | HTTP(CRM) | 고객 이력 조회 |
| 분기 | Switch | 담당 팀 라우팅 |
| 액션 | Slack·Gmail | 알림 + 1차 답변 |

에이전트가 *도구 호출 순서를 스스로 결정*하는 패턴이라 디버깅이 까다롭다. 실행 로그를 한 단계씩 펼쳐 보며 프롬프트를 좁혀야 안정된다.

## 레시피 4 — 콘텐츠 파이프라인

**Schedule**로 주제 큐를 꺼내 **3개의 LLM Chain**(개요 → 초안 → 교정)을 직렬로 돌리고, 완성본을 WordPress 초안으로 올린다. AI 글쓰기를 흐름에 박아 넣는 구조다.

- **체인 1**: 주제 → SEO 개요(H2 구조)
- **체인 2**: 개요 → 본문 초안
- **체인 3**: 초안 → 톤·맞춤법 교정
- **액션**: WordPress REST API로 비공개 초안 저장

콘텐츠 자동화의 품질 기준과 사람 검수 지점을 어디에 둘지는 별도 글에서 따로 다룰 만큼 중요하다. n8n은 *생성*을 자동화하되 *발행 승인*은 사람에게 남기는 구성이 안전하다.

## 레시피 5 — 데이터 모니터링 알림

**Schedule**로 외부 API(가격·재고·지표)를 주기 호출하고, **AI Agent**가 "임계치 돌파·이상 패턴"을 판단해 Telegram으로 자연어 알림을 보낸다. 단순 숫자 비교를 넘어 *맥락을 붙인 알림*이 핵심이다.

- **트리거**: Schedule (10분 간격)
- **도구**: HTTP Request(지표 수집)
- **LLM 역할**: 임계치 판단 + "왜 중요한지" 한 줄 코멘트
- **액션**: [Telegram](https://telegram.org) Bot 전송

## n8n vs 다른 자동화 — 언제 n8n인가

n8n이 항상 정답은 아니다. 같은 자동화를 세 도구로 만들어 본 비교는 <Link href="/ko/blog/zapier-vs-make-vs-n8n">Zapier vs Make vs n8n 비교</Link>에 데이터로 정리해 뒀다. 요약하면, *코드를 직접 박고 워크플로우를 Git으로 관리하며 실행량이 많은* 작업일수록 n8n이 유리하다. n8n을 1인 운영 자동화 스택의 어느 칸에 둘지는 <Link href="/ko/blog/solo-developer-automation-stack">1인 개발자 자동화 스택</Link>에서 전체 지형과 함께 보면 선명하다.

## 자주 묻는 질문 (FAQ)

### n8n에서 AI Agent 노드와 LLM Chain은 무엇이 다른가요?

AI Agent 노드는 LLM에 *도구 목록*을 함께 줘서 모델이 스스로 호출 순서를 정하게 하는 구조이고, LLM Chain은 정해진 입력을 받아 *판단·요약만* 수행한다. 도구를 능동적으로 부를 필요가 있으면 AI Agent, 단순 변환·요약이면 가벼운 Chain으로 충분하다. 자율성이 필요 없는데 Agent를 쓰면 비용과 디버깅 부담만 커진다.

### n8n AI 워크플로우에 어떤 LLM을 연결할 수 있나요?

OpenAI, Claude(Anthropic), Google Gemini 등 주요 모델을 자격증명만 등록하면 AI Agent·LLM Chain 노드에 연결할 수 있다. 비용·응답 속도·한국어 품질을 보고 고르면 되고, 같은 워크플로우에서 모델만 바꿔 끼우는 것도 가능하다. 민감 데이터를 다룬다면 셀프호스트 + 로컬·사내 모델 조합도 검토할 수 있다.

### 코딩을 모르는데 n8n AI 에이전트를 만들 수 있나요?

기본 레시피는 노드를 캔버스에 배치·연결하는 노코드 작업이라 코딩 없이 가능하다. 다만 외부 API를 HTTP Request로 직접 부르거나 응답을 가공할 때 JSON 구조와 표현식을 어느 정도 읽을 줄 알아야 막히지 않는다. 메일 분류 같은 단순 레시피부터 시작해 표현식에 익숙해진 뒤 복잡한 에이전트로 넘어가는 순서를 권한다.

### n8n AI 에이전트 운영 비용은 얼마나 드나요?

크게 두 가지다. n8n 자체는 셀프호스트하면 무료(서버 자원·운영 시간이 실질 비용), 클라우드는 월 구독이다. 여기에 LLM API 호출 비용이 별도로 붙는데, 토큰 사용량에 비례한다. 모니터링처럼 호출이 잦은 레시피는 모델을 가벼운 것으로 쓰고, 콘텐츠 생성처럼 품질이 중요한 곳만 고성능 모델을 쓰는 식으로 분리하면 비용을 통제할 수 있다.

## 마무리

n8n의 AI Agent 노드는 "자동화"와 "에이전트" 사이의 문턱을 크게 낮췄다. 핵심은 화려한 기능이 아니라 *하나의 골격을 다섯 가지로 변주*하는 감각이다. 트리거 하나, 도구 하나만 바꿔 끼우며 작은 레시피부터 돌려 보면, 어느새 내 업무의 반복 구간이 LLM에게 넘어가 있다. 코드로 같은 에이전트를 직접 짜 보고 싶다면 <Link href="/ko/blog/claude-mcp-guide">Claude MCP 가이드</Link>로 도구 연결의 표준 방식까지 넓혀 볼 수 있다.
